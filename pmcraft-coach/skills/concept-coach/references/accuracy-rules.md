# 网络知识准确性保障（搜索 5 层 + 事实可追溯）

> SKILL.md 步骤 3"按需搜索判定"的细则。核心原则：**类比和结构是"讲法"，只求传神；定义、现状、数据是"事实"，必须可追溯。**

---

## 触发条件（满足其一即搜索）

1. 概念可能过时：新概念 / 具体版本号 / **2025 后技术**（模型知识截止线）
2. 用户要求查证："查一下现在主流做法" / "这个数据准确吗"
3. 事实型细节不确定：数据、时间、公司名、版本号——**不编造**，搜索或标注

不触发：经典概念（API、数据库、缓存……）直接讲；类比本身永远不需要搜索（是讲法不是事实）。

## 准确性保障 5 层

### ① 多源交叉验证
关键事实 **≥2 个独立来源一致**才作为事实讲出；单源不采信（对齐 thinking-coach 材料包"≥2 次搜索"先例）。
- 两个来源互相冲突 → 不采信任何一方，标注"不同来源说法不一"或继续搜
- 2 次搜索后仍无一致结论 → 按第 ④ 层处理

### ② 权威源优先
官方文档 / 官网 / 标准组织 > 一手技术博客 > 二手文章、论坛。
冲突时以权威源为准，并在存档 sources 中说明取舍。

### ③ 时间戳
现状类陈述一律带时间："截至 2026-08"。
技术现状随时在变——"目前主流是 X"这种话没有时间戳，三个月后就可能误导人。

### ④ 查不到就标注
搜索无果 / 来源冲突无法裁决 → 明说：
> "这个我查到的是 [X]，但来源说法不一/没找到权威来源，我不确定——建议查 [具体渠道 Y]。"

**不硬编**。宁可承认不知道，不给出看着像样的假事实（对齐"所言必有所据"）。

### ⑤ 讲法与事实分层
- **讲法**（类比、结构、角度）→ 不需要搜索，讲错只影响传神，换一个即可
- **事实**（定义、现状、数据、时间、公司、版本）→ 必须可追溯：模型固有知识 or 搜索来源，两者都不是 → 去掉或标注

## 存档闭环

学习记录 frontmatter 记（与 SKILL.md 步骤 7 存档模板一致）：
```yaml
sources: [搜索来源 URL 或 无]
```

有搜索来源时填实际 URL 列表（逗号分隔）；未触发搜索填"无"。任何讲出的事实都能回溯：哪来的、什么时候查的。retro 复查也有据可查。

## 门禁挂钩

输出前检查第 4 条（准确优先）细化为：**事实性陈述必须能说出处**——说不出处的事实细节，去掉或标注"不确定"。类比性陈述只要求"不误导"（不说出与事实相反的意思）。
