# 对比细则（"跟 X 比着讲"）

> 触发：用户说 "跟 MySQL 比着讲" / "它俩有啥区别" / "哪个好" / "XX 和 YY 有啥不同" 等。

## 格式（严格按此结构）

```markdown
**[概念 A]** — [类比一句]
**[概念 B]** — [类比一句，用**同一个**类比域]

**相同**：[真正共同点，一句]
**不同**：[最关键的一条差异，不是列表]

**用 A 时**：[用户场景一句]
**用 B 时**：[用户场景一句]
```

## 规则

1. **同一类比域**：A、B 必须用同一个世界的类比（都用厨房、或都用商场、或都用学校）——不同域无法真正比较。这是 eli-compare 的核心纪律。
2. **不同点只给最要命的一条**：用户要的是"选哪个"，不是差异清单。多问"哪条差异决定了选择"，只讲那条。
3. **用 A 时 / 用 B 时**：落到用户的真实场景（"你排期紧就选 A"），不是抽象描述。
4. 用户没说 B 是谁 → 反问一次："跟谁比？"（"跟 MySQL 比"）——不猜。
5. 输出前过门禁检查（SKILL.md 步骤 5）。
