# 拷问话术库

> grilling-coach 构思每轮问题时参考。推荐答案写作原则 + 拷问话术模板。
> 四原则与 SKILL.md 第 3 层「规则二」一致——SKILL.md 为权威定义，本文件为展开示例与话术库，不另立标准。

## 推荐答案写作四原则（每题必过）

1. **具体可反驳**：给出明确结论，不用形容词策略。
   - ✗ "低定价策略" → ✓ "9.9 元 + 首月免费"
   - ✗ "先做核心功能" → ✓ "MVP 只做打卡 + 提醒两件事，积分/社区后置"
2. **一句话理由**：为什么推荐这个——讲机制，不讲情怀。
   - ✓ "推荐 9.9 元：打卡类功能用户价格锚点低，且首月免费降低启动阻力"
3. **标注依赖假设**：此推荐建立在什么未知事实上（假设不成立则推荐失效）。
   - ✓ "（依赖假设：获客主要靠存量班级转化；若靠投放获客，定价可上探）"
4. **决策权归用户**：推荐只是参考。用户可采纳、可反驳、可自定义。

## 拷问话术模板

### 方案选择型

- "A 和 B 的代价差在哪？你放弃 B 时失去的是什么？"
- "如果 B 其实是更好的选择，什么证据会让你改判？"
- "这个选择一旦做了，哪个下游决策会被锁死？"

### 参数设定型

- "这个数值的上下界是什么？超出哪个范围就失去意义？"
- "定了 X 之后，哪些下游决策跟着变？"

### 边界定义型

- "不做的部分，触发什么条件会纳入？"
- "排除这个用户群，他们的替代方案是什么？他们会流失到哪？"

### 前提假设型

- "这个前提不成立的话，方案里什么会崩塌？"
- "外部依赖的交付承诺，你拿到书面确认了吗？"

### 静默假设追问（揪 [隐]）

- "你刚才说'下个月上线'——这个排期是谁定的？有资源承诺吗？"
- "'用户会愿意'——这个判断的证据是什么？没有证据的话它是个假设。"

### 防伪确定（用户断言式回答）

- "你听起来很确定——是什么让你这么确定？有看过反例吗？"

### 黄金时刻（用户反驳推荐答案）

- "你不同意的点具体是什么？如果我的推荐错了，正确的判断是什么？"
- 不辩护；更新选项空间后继续。

## 选项设计规则

- 每问 2-4 个**具体**选项（不是空泛"是/否"，除非问题真二选一）。
- 选项要覆盖"用户会现实选择的"方向——从用户已说的话里提取选项，别发明用户不会选的选项。
- 用户永远可以自定义（"Other"）——选项只是脚手架。
