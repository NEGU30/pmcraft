# grilling-coach 评价测试用例

> 人工评估用（AI 不读取）。覆盖触发准确性 / 输出确定性 / 边缘情况。版本发布前逐条人工验证。

## 正向触发（必须激活 grilling-coach）

| # | 用户输入 | 预期行为 |
|:---|:---|:---|
| 1 | 拷问我的方案：课程打卡功能 | 进入建树流程（阶段 0），输出设计树待确认 |
| 2 | 拷问我的想法，文档在 ./plan.md | 读取文档 → 建树 → 树确认 |
| 3 | grill me | 索要方案或文档路径 → 建树 |
| 4 | 挑战一下我的方案：自研还是采购 | 建树，首轮前沿含该决策 |
| 5 | 方案拷问：做小程序还是 App | 建树，首轮前沿含该决策 |
| 6 | 拷问我的计划：下个月上线的冷启动方案 | 建树，静默假设搜刮揪出时间/渠道假设（`[隐]`） |

## 负向触发（必须不激活 grilling-coach）

| # | 用户输入 | 预期行为 |
|:---|:---|:---|
| 1 | 帮我分析一下思路，聊聊自动驾驶 | 转 thinking-coach（无方案/计划可拷） |
| 2 | 讲讲什么是 MVP | 转 concept-coach（概念提问，无决策树可建） |
| 3 | 审查我的方案文档 | 转 doc-reviewer（审查请求，非拷问） |
| 4 | 写需求：课程打卡功能 | 转 req 域（表述含"需求"，排他条款命中） |
| 5 | 做原型：打卡页面 | 转 proto 域（表述含"原型"，排他条款命中） |
| 6 | 心情不好，想找人聊聊 | 转 thinking-coach（纯倾诉，无决策树可建） |

## 边缘查询（边界行为）

| # | 用户输入 | 预期行为 |
|:---|:---|:---|
| 1 | 只有触发词无方案："拷问" | 索要方案或文档路径，不自行发明方案 |
| 2 | 方案文档路径不存在 | 告知路径不可读，请用户给正确路径或口头描述 |
| 3 | 一轮内全部答"跳过" | 整棵子树标 `[跳]`，前沿推进，清单记录"PM 主动跳过，未视为决策" |
| 4 | 用户说"一题一题来" | 切换 AskUserQuestion 逐题弹窗（2-4 选项 + 自定义）；工具不可用则纯文本同格式 |
| 5 | 拷问中用户说"先这样，退出" | 输出部分决策清单（标注"未完成：仍有 N 个决策未定"），可「继续拷问」恢复 |
| 6 | 树 >30 节点 | 提示选核心分支聚焦或分批拷问，不硬问 30+ |
| 7 | 某前沿问题依赖的事实查不到 | 标"未查到公开信息，列为待验证假设"+ 验证线索，不编造、不反问"你知道吗" |

## 输出确定性断言

- 每轮输出必须：锚定用户原话 + 编号前沿问题 + 每题 2-4 个具体选项 + `➡️ 推荐答案`（过四原则）。
- 结束输出必须按 `../templates/decision-list-template.md` 四段结构：已定决策（含依据）/ 待验证假设（含验证线索）/ 被跳过分支 / ⚠️ 覆盖说明。
- 树标注符号必须与 `./decision-tree-guide.md` 第 5 节一致：`[定]` / `[定-按推荐]` / `[待]` / `[隐]` / `[跳]` / `[盲区]`。
- 决策清单确认前不执行任何行动。
