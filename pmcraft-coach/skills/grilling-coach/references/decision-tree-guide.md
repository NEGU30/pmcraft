# 设计树构建指南

> grilling-coach 阶段 0 建树时必须读取本文件。核心：把方案映射成决策树——每个决策分支挂出依赖它的子决策，直到每个分支都显式收敛。

## 1. 决策点判据

一个东西算不算"决策点"，必须**同时满足**：

1. **存在 ≥2 个现实可选的结论**（A 或 B 或 C，不是"只能这么做"）
2. **选择影响下游**（改变其他决策的选项空间 / 工作量 / 风险）

不满足 → 不是决策节点，是背景信息。背景信息不拷问，记入方案上下文即可。

**反例**：
- "用户需要登录"——如果系统规范强制，无选择 → 背景信息
- "功能要上线"——如果是既定事实 → 背景信息
- "上线时间 4 周 vs 8 周"——有选择、影响排期和范围 → 决策点

## 2. 四类决策点

| 类型 | 定义 | 例子 |
|:---|:---|:---|
| 方案选择型 | 在多个实现/做法中选一个 | 自研 vs 采购；做 App vs 做小程序 |
| 参数设定型 | 给一个参数定值 | 定价 9.9 vs 19.9；打卡周期 7 天 vs 30 天 |
| 边界定义型 | 划定做/不做的范围 | 目标用户；首期不做哪些功能 |
| 前提假设型 | 外部依赖/前提是否成立 | 用户愿意付费；供应商能按时交付；政策允许 |

## 3. 依赖识别规则

**决策 D2 依赖 D1，当且仅当 D1 的结论会改变 D2 的选项集合或评估标准。**

- "发布渠道"依赖"目标用户"（用户决定渠道）
- "定价"依赖"成本结构"（成本决定定价下限）
- "打卡奖励机制"依赖"目标用户"（不同用户群体激励不同）

**依赖方向**：只允许自上而下（D1 → D2）。发现**环**（A 依赖 B 且 B 依赖 A）→ 拆环：把环中任意一个决策拆成前提假设型，声明其外部性。

**依赖 ≠ 相关**：没有"改变选项集合或评估标准"的关系不构成依赖。只是"都重要"的两个决策不互相依赖。

## 4. 静默假设清单（主动搜刮，不等用户暴露）

用户描述方案时没说出口、但实际暗含选择的，主动揪出并标 `[隐]`：

| 类别 | 典型暗含 | 例子 |
|:---|:---|:---|
| 时间假设 | "X 时候上线"是已定还是随口 | "下个月上线"——排期 4 周还是 8 周没人确认过 |
| 资源假设 | 人力/预算默认存在 | "两个开发"——谁说的？预算批了吗 |
| 范围假设 | 方案里"不做"的部分 | "先不做积分商城"——是主动排除还是忘了 |
| 用户假设 | 用户行为/意愿被默认 | "用户会愿意为打卡坚持"——有证据吗 |
| 渠道假设 | 获客渠道被默认 | "自然流量就够了"——冷启动靠什么 |

发现的隐含选择 → 标 `[隐]`，进轮次拷问。**铁律：没有静默假设**——每一个隐含选择都必须显式化，除非用户确认跳过。

## 5. 树形标注

| 标记 | 含义 | 谁设的 |
|:---|:---|:---|
| `[定]` | 已定决策 | 用户已明确拍板（含拷问中拍板） |
| `[定-按推荐]` | 已定，按推荐答案 | 用户"就按你说的" |
| `[待]` | 待定，进前沿 | 建树时 |
| `[隐]` | 隐含选择，需确认 | 静默假设搜刮发现 |
| `[跳]` | 跳过 | 用户主动跳过，不再拷问 |
| `[盲区]` | 结论依赖缺失的内部情报 | 信息盲区诊断发现 |

## 6. 信息盲区诊断

对每个 `[待]`/`[隐]` 决策点，检查"结论依赖的事实是否已知"：

- **依赖公开可查事实**（市场规模、竞品公开行为、技术可行性、行业惯例）→ 不标盲区，拷问轮次中自查（WebSearch/WebFetch 或派子代理）。
- **依赖内部情报且缺失**（成本结构、团队能力、组织约束、预算、内部用户证据）→ 标 `[盲区]`。拷问时该决策的推荐答案标注"此推荐建立在未知事实上"，轮次结束处提示补情报路径（「竞品分析」/「商业分析」/内部确认）。

## 7. 前沿计算规则

**前沿 = 所有直接依赖均已 `[定]`/`[跳]` 的待定决策**（含 `[待]` 和 `[隐]`）。

- 每轮问**整个前沿**，编号列出，等用户回答后再重算。
- 有依赖的决策属于**后续轮次**，本轮不问——问依赖未决的问题 = 猜测还没听到的答案。
- 用户回答后：已定决策把前沿向外推（push the frontier outward），解锁依赖它们的问题（unblock questions that depended on them）。
- 一个问题的答案依赖本轮仍开放的另一问题 → 它属于更晚的轮次，不在本轮。
- 运行中的事实查证（子代理未回）是未定前置：只有它的下游问题等它，其余前沿照常问。

## 8. 规模控制

- 决策节点 >30 → 请用户选核心分支聚焦，或分批拷问（先主干后支线）。
- 树确认后告知规模："这棵树有 N 个决策点，预计 X 轮问完。"
