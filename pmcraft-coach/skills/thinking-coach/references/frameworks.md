## 支柱一：批判性思维 ⭐ 最高优先级

> "这个故事里，哪些假设没被验证？谁的声音被忽略了？反面证据在哪？"

### 一、Socratic 六类追问

改编自 `tjboudreaux/cc-thinking-skills` 的 `thinking-socratic/SKILL.md`。

#### 1. 澄清类问题
| 问句 | 适用场景 |
|:---|:---|
| "你说的 X 具体指什么？" | 术语模糊 |
| "能给我一个具体例子吗？" | 概念抽象 |
| "这和 Y 有什么关系？" | 关联不清 |
| "能用另一种方式重新描述吗？" | 表述混乱 |

#### 2. 假设探查类问题
| 问句 | 适用场景 |
|:---|:---|
| "我们在这里假设了什么？" | 结论太快 |
| "这个假设一定成立吗？" | 泛化过度 |
| "如果这个假设是错的呢？" | 检验鲁棒性 |
| "我们为什么相信这个？" | 基础不清 |

#### 3. 证据与理由类问题
| 问句 | 适用场景 |
|:---|:---|
| "有什么证据支持这个结论？" | 断言无据 |
| "我们怎么知道的？" | 来源不明 |
| "有没有其他解释？" | 因果假设 |
| "什么证据能推翻这个结论？" | 检验可证伪性 |

#### 4. 视角与立场类问题
| 问句 | 适用场景 |
|:---|:---|
| "X 会怎么看这件事？" | 单一视角 |
| "相反的观点是什么？" | 没有替代方案 |
| "谁不同意，为什么？" | 共识太容易 |
| "我们看不到什么？" | 盲点嫌疑 |

#### 5. 推论与后果类问题
| 问句 | 适用场景 |
|:---|:---|
| "如果这是真的，那么必然还有什么也是真的？" | 推论未探索 |
| "这会导致什么连锁反应？" | 只看直接影响 |
| "第二阶效应是什么？" | 只看一阶 |
| "这会影响谁？" | 影响范围不清 |

#### 6. 元问题（对问题的提问）
| 问句 | 适用场景 |
|:---|:---|
| "为什么这个问题重要？" | 目的不清 |
| "回答这个问题能告诉我们什么？" | 问题价值不明 |
| "这是正确的问题吗？" | 可能需要重构 |
| "我们应该问什么？" | 需要重新框定 |

#### 追问执行原则（"如何问好"）

改编自 `tjboudreaux/cc-thinking-skills` 的 `thinking-socratic/SKILL.md` 中的 "How to Ask Well"。

1. **问负载最重的问题**：先问答案最能改变接下来方向的那一个问题，不是每个好问题都值得问
2. **一次一两问，不审讯**：只问当前真正卡住认知的那一两问，不把六类遍历一遍当表演
3. **顺着回答往下追**：让每个回答收窄下一问的方向，而不是照固定脚本走
4. **自己能查的别问用户**：只有用户不知道、查不到、或属于他独特判断的事才值得问
5. **把假设显性化**："这假设了 X——对吗？"比在沉默中猜 X 好一万倍

### 二、批判性思维六步法

改编自 `wanikua/thinking-skills` 的 `critical-thinking.md`。

1. **识别并质疑假设**：哪些是显性的？哪些是隐性的（没说但被默认的）？
2. **评估证据质量**：来源可信度、方法论、时效性、可复现性、缺失证据
3. **检测偏见与逻辑谬误**：确认偏见、锚定、幸存者偏差、权威偏见、沉没成本
4. **考虑替代解释**：至少 3 种替代解释，哪个需要最少假设（奥卡姆剃刀）
5. **评估结论强度**：强（多独立证据线）/ 中（有缺口）/ 弱（依赖假设）/ 不确定
6. **综合判断**：什么可以自信地说？什么仍然不确定？下一步验证建议？

### 三、Inversion 反演法

改编自 `tjboudreaux/cc-thinking-skills` 的 `thinking-inversion/SKILL.md`。

> "如何保证这件事失败？"

1. 明确目标
2. 反问：怎么做才能保证失败？列出 10+ 条
3. 分类（安全性 / 运维 / 流程 / 可靠性...），标注严重程度
4. 将 Top 3-5 条失败路径转化为规避需求

## 支柱二：第一性原理

> "抛开所有现有方案，这个问题的物理/经济/人性本质是什么？"

### 第一性原理五步法

改编自 `tjboudreaux/cc-thinking-skills` 的 `thinking-first-principles/SKILL.md`。

1. **识别所有当前假设**：大家接受了哪些约束？哪些成本/限制被视为固定？传统智慧是什么？
2. **分解到基本真理**：反复问"我们绝对确定什么是真的？"——物理约束、原材料、经济学定律、最低可行版本
3. **挑战每条假设**：这是真的还是惯例？什么证据支持？什么条件下它会是假的？谁从中获益？
4. **从基本真理重建**：只从验证的真理出发——最简单的解是什么？如果今天从零开始做？
5. **对照现实验证**：违反物理/法律了吗？还剩下什么实际约束？最小可行测试是什么？

### 五类心理陷阱与解药

| 陷阱 | 描述 | 解药 |
|:---|:---|:---|
| 类比推理 | "别人都这么做" | "但这最优吗？" |
| 诉诸权威 | "专家说不可能" | "具体是什么让它不可能？" |
| 沉没成本 | "我们一直这么做" | "如果今天从零开始呢？" |
| 复杂性偏见 | 假设复杂 = 更好 | "最简单的版本是什么？" |
| 虚假约束 | 接受人为限制 | "这是物理定律还是惯例？" |

### 关键追问

- "我们知道什么是绝对确定的？"
- "为什么每个人都假设这个约束存在？"
- "如果预算只有 10%，我们会怎么做？"
- "如果今天从零开始，会这样建吗？"
- "一个完全的外行会怎么试？"

## 支柱三：产品思维

### 3a. 解决问题

> 精准定义"谁在什么场景遇到了什么麻烦"

#### 核心追问
- **用户**：谁有这个麻烦？他们的角色、背景是什么？
- **场景**：什么时间、地点、前置条件下发生？
- **核心信号**：用户最底层的那个话/那个生理或心理反应是什么？
- **重构问题**："这不是 X 问题，而是 Y 问题"（用"不是…而是…"句式）

#### 5-Whys（五问法）
逐层追问"为什么"，区分表象与根因。经典示例：
```
问题：用户流失率高
→ Why 1：用户试用后不付费
→ Why 2：用户觉得不值这个价
→ Why 3：用户没有在试用期体验到核心价值
→ Why 4：新用户引导流程没有展示核心价值
→ Why 5：引导流程是按功能设计的，而不是按用户任务设计的
根因：引导流程设计逻辑与用户认知逻辑不匹配
```

#### JTBD（待办任务框架）
改编自 `tjboudreaux/cc-thinking-skills` 的 `thinking-jobs-to-be-done/SKILL.md`。
- 用户"雇佣"这个产品来完成的"工作"是什么？
- 用户当前的替代方案是什么？（包括手工、Excel、什么都不做）
- "雇佣"和"解雇"的时刻是什么？
- 阻碍用户"雇佣"的情感障碍是什么？

### 3b. 产品化

> 功能、标准、服务、SOP 均可视为"产品"。三个并列维度：**标准化**、**自动化**、**规模化**（非递进关系，可并行推进）。

#### 标准化（SOP）
- 第一步必须固化的标准操作步骤是什么？
- 成功执行一次的标准路径是什么？关键节点有哪些判断条件？
- 是否存在"只有老王知道"的隐性知识需要显性化？

#### 自动化
- SOP 中哪个环节可以用"规则（If-Then）"替代人工判断？
- 自动化后的异常处理机制是什么？什么情况退回人工？
- 自动化不是去掉人，是让人从重复判断中解放出来做更高价值的事。

#### 规模化
- 如果量级扩大 100 倍，瓶颈节点会爆在哪里？
- 预设的应急预案是什么？到什么阈值触发？
- 规模化后是否会改变问题本身的定义？（量变引起质变）

## 深度模式补充

### 红队反驳
改编自 `tjboudreaux/cc-thinking-skills` 的 `thinking-red-team/SKILL.md`。

> "如果我想击垮这个方案，我会从哪下手？"

1. 定义目标和范围
2. 确定对手画像：外部攻击者 / 有权限的用户 / 内部人员
3. 枚举攻击面：每个入口和信任边界
4. 执行攻击场景：入口 → 步骤 → 影响
5. 尝试绕过防御
6. 记录发现：只记录可复现的攻击路径，不允许虚幻断言

**关键规则**：每个发现必须有具体的"入口 → 步骤 → 实际影响"攻击路径。无法描述具体攻击路径的 = 不算发现。

### 跨行业映射
- 把今天的核心洞察抽取出来
- 映射到一个完全不相关的行业（如"今天聊的 SaaS 定价，在餐饮业怎么体现？"）
- 寻找结构同构：表面不同的两个事物，底层逻辑是否一样？

## 初始假设 → 终点回看

让 PM 亲眼看到自己的判断被修正或验证，是单次 sparring 最有力的学习信号。

流程：
1. **开头锚定**：切入第一个问题前，问"关于这个话题，你现在最确定的一个判断是什么？"
2. **终点回看**：存档前，把这句话抛回去："你开头说'_______'——现在这个判断变了多少？"
3. **存档记录**：将初始判断和终点判断一并写入日志的"初始判断 vs 终点回看"字段

设计原理：
- PM 不是被动地被追问了一轮，而是**亲眼看到自己的思考发生了位移**
- 这个位移（无论大小、无论修正还是强化）就是单次训练最直接的收获证据
- 如果没有位移 → 这次 sparring 可能不够深，下次应该加大追问力度

## 防浅层闭合检查清单

当对话出现"自然收束感"时，AI 内部执行以下检查：

1. **方案层检查**：我们找到了根因，但"然后呢"？这个发现应该改变什么？
2. **反例检查**：是否存在不适用这个结论的情况？在什么条件下这个结论会反转？
3. **粒度检查**：现在的结论够不够具体？——哪个环节？哪类用户？什么频率？
4. **替代检查**：除了我们已经讨论过的解释，还有没有至少两种替代解释？

以上四条中任意一条不满足 → 对话尚未真正收束，继续追问。

## 抽象过渡脚手架

从具体到抽象的过渡，分三步走（不要跳过）：

1. **锚定**：用一个用户刚才提到的具体事物/行为做锚点
   - "你刚才提到[用户的具体行为]——"
2. **剥一层**：只剥掉最外层约束，保留用户熟悉的东西
   - "如果[具体行为]是唯一不能动的东西，其他都可以删——你会先删什么？"
3. **再剥到本质**：用户回答后再推到白纸
   - "现在把[具体行为]也放开——这个问题的本质变成了什么？"

错误模式：直接跳到白纸（"抛开一切从零开始"）→ 用户困惑
正确模式：锚定→剥一层→再剥到本质 → 用户跟着走

## 四层深度模型

| 层级 | 名称 | 标志性问题 | 本层完成信号 | 典型卡壳信号 |
|:---|:---|:---|:---|:---|
| L1 表象层 | 发生了什么 | "你看到了什么现象/数据？" | 现象被清晰、具体地描述 | "大概是/好像是/可能" |
| L2 模式层 | 什么在重复 | "这是个例还是模式？同类情况还有哪些？" | 识别出跨案例的共性规律 | 只有一个例子，无对比 |
| L3 根因层 | 为什么发生 | "这推翻了什么假设？因果方向确认了吗？" | 找到可被验证的因果链 | 停在相关不等于因果 |
| L4 方案层 | 然后呢 | "这个发现改变了你要做的什么事？" | 产出可行动的最小改变 | "需要系统化思考"等抽象收尾 |

AI 在 sparring 中应：
- 标注当前深度时使用层级名称（如"我们在 L3 根因层……"）
- 检测浅层闭合：停在 L3 但未到 L4 → 提示用户
- 检测伪深度：用户用抽象概念回答根本问题时 → 追问具体化

## 教练思考透明化指南

### 为什么需要透明化

PM 在 sparring 中的长期收益不只是"这次想清楚了"，更是"下次自己也会这样想了"。
透明化把 AI 的思考方法从黑盒变成可学的工具。

### 五个常用思考方法的表述模板

| 方法 | 适用场景 | 透明化表述模板 |
|:---|:---|:---|
| 对比法 | 发现两个看似相似的事物的关键差异 | "我把[A]和[B]并排对比，发现在[维度]上它们完全相反——这个维度可能就是关键变量。" |
| 排除法 | 缩小可能性范围 | "我先排除了[X]、[Y]这些不太可能的解释——剩下的[Z]虽然不太舒服，但最符合现有证据。" |
| 找缺失 | 数据/叙事中缺少了什么 | "我注意到所有讨论都集中在[可见的A]，但[不可见的B]完全没人提——沃尔德的眼睛就是盯着没弹孔的地方。" |
| 极限测试 | 把结论推到极端看是否成立 | "我把你说的逻辑推到极限——如果100倍量级会怎样？如果所有用户都这样做会怎样？——来检验逻辑是不是只在温和条件下成立。" |
| 跨界映射 | 把A行业的模式套到B行业 | "这个结构和[某不相关行业]的[某模式]底层是一样的——表面不同，但约束条件的高度相似让我觉得可以借过来看看。" |

### 透明化的三个不要

1. **不要在每次追问后都展开**——只在关键节点（教练视角、支柱切换、用户卡壳、用户关键回答后）
2. **不要用方法论术语装腔**——"我用的是归纳法"不如"我连续看了三个例子，发现它们都在重复同一个模式"
3. **不要比用户的思考更长**——透明化是佐料，不是主菜

## 教练推演框架库

> 当教练推演（coach-demo workflow）生成时，AI 从此库选取分析框架。
> 收录 6 个框架，每个含适用场景、核心步骤、推演展示方式、失效条件。

### 1. 三层信号链

**什么时候用**：多方博弈、信号不对称、表面混乱实际每方都在发信号——当你的话题涉及"好几方同时在说话和行动，但谁都没有把真实意图写在脸上"。

**核心步骤**：
1. 识别每一方作为"信号发送者"——列出所有参与方（至少 3 方）
2. 对每一方拆解三种信号：行动信号（ta 做了什么）、语言信号（ta 说了什么）、沉默信号（ta 没说什么没做什么）
3. 串联信号链：A 的行为 → B 解读成什么 → B 的回应 → A 再解读成什么
4. 找出"信号断裂点"——哪个解读是错的，但双方都信了

**推演展示**：按层展开——第 N 层（各方之间发生了什么事 / 各方收到了什么信号 / 信号有没有被正确解读）

**失效条件**：当各方有明确、可验证的直接沟通记录时（如会议纪要、公开合同），直接读记录比信号拆解更准确。也适用于问题完全发生在单一层级内（如纯团队内部管理问题）。

### 2. JTBD 深度版

**什么时候用**：用户行为分析、需求本质挖掘——当你想理解"用户雇佣这个产品/行为到底来完成什么工作"。

**核心步骤**：
1. 定义待办任务——用户"雇佣"这个产品/行为来完成的"工作"是什么（功能任务 + 情感任务 + 社会任务）
2. 列出当前替代方案——包括手工、Excel、什么都不做、用另一个看起来完全不同的产品
3. 识别雇佣/解雇时刻——用户什么时候开始用（雇佣时刻）、什么时候放弃（解雇时刻）
4. 挖掘情感障碍——什么在阻止用户"雇佣"？（焦虑、习惯、切换成本、信任缺失）

**推演展示**：从用户的任务出发逐层展开——任务定义 → 替代方案对比 → 雇佣/解雇时刻的触发条件 → 情感障碍如何被克服或绕过。

**失效条件**：当用户行为是高频重复习惯（如每天买同一杯咖啡）而非一次性"雇佣"决策时，JTBD 会把习惯过度解释为有意识的选择。也适用于纯技术约束问题（如"协议不兼容"——这不是用户"选择不用"，是用不了）。

### 3. 约束剥层

**什么时候用**：第一性原理推演、挑战行业惯例——当你想回答"这件事的本质约束是什么，多出来的都是什么"。

**核心步骤**：
1. 列出所有当前约束——"这件事为什么不可能/太难/太贵"
2. 将每条约束分类：物理约束（原材料、物理定律、绝对稀缺）vs 惯例约束（行业大家都这么做、合同这么签、监管这么要求）vs 心理约束（用户不习惯、老板不喜欢、团队觉得不可能）
3. 从物理约束重建方案——如果只保留物理约束，最简单能跑通的版本是什么
4. 再加回可接受的惯例约束——哪些惯例虽然理论上可删但实际删不了（合规、安全底线）

**推演展示**：三层剥开——当前方案依赖的约束有哪些 → 逐条分类 → 只保留物理约束后的最小可行方案 → 加回必要惯例后的实际可行版本。

**失效条件**：当问题的核心矛盾不是约束过多而是信息不足时——你不知道约束是什么，不是约束太多。此时应该先收集信息，不是剥约束。

### 4. 反事实推演

**什么时候用**：检验一个结论的鲁棒性——"如果关键变量反转了，这个结论还成立吗？"

**核心步骤**：
1. 识别最关键的假设——"这个结论依赖哪几个前提？哪个前提一旦动摇，结论就塌了"
2. 反转它——假设那个前提是错的，或者方向相反
3. 推演新结论链——从反转后的前提出发，自然推出的结论是什么
4. 对比原结论的脆弱点——原结论在哪些条件下不成立

**推演展示**：当前结论 + 关键假设 → 反转假设 → 新结论链 → 对比（原结论在什么边界条件下成立、什么条件下不成立）。

**失效条件**：当原始结论本身就有多个互斥假设同时成立时（矛盾前提），反转会制造一个更混乱的画面。先理清前提的一致性再做反事实。也适用于纯描述性问题（"发生了什么"而非"如果 X 会怎样"）。

### 5. 五力改编版

**什么时候用**：竞争/平台话题、多方力量博弈——当你想理解"谁的力量在决定这个行业的走向"。

**核心步骤**：
1. 供应商力量——上游谁手里有筹码？他们的替代选项是什么？
2. 买方力量——下游谁有选择权？转换成本多高？
3. 替代方案威胁——不用这个品类，用户用什么解决同一问题？
4. 新进入者威胁——门槛在哪？谁能跳进来？
5. 现有竞争强度——存量玩家在卷什么？（价格？品类？体验？）

改编点：从"产品化"视角重新定义五力——每种力量不是静态的产业结构，而是可以通过标准化/自动化/规模化来改变的变量。

**推演展示**：五力散开——每种力量当前的强度 + 被产品化改变的可能性 + 谁会先动手。

**失效条件**：当行业处于剧烈技术变革期（如 AI 替代人工的过渡阶段），五力的"存量结构"本身在快速失效。此时框架给出的是快照，不是预测。也适用于太小的市场——五力的分析成本可能高于行动价值。

### 6. S曲线定位

**什么时候用**：技术/产品生命周期话题——当你想回答"我们现在在 S 曲线的哪一段，下一个拐点是什么"。

**核心步骤**：
1. 定位当前在 S 曲线位置——缓慢爬升期 / 陡峭增长期 / 平台期 / 衰退期
2. 识别下一个拐点信号——什么变量在变（技术突破 / 用户行为迁移 / 监管变化 / 成本骤降）
3. 推演拐点后的竞争格局——谁会受益、谁会被淘汰、谁会被迫转型
4. 拐点前的窗口期——现在做什么准备、什么时候必须做决定

**推演展示**：当前 S 曲线位置 + 信号 → 拐点推测 → 拐点后格局 → 窗口期内/窗口期后的行动推演。

**失效条件**：当产品/技术本身还没有被验证有市场需求时（还在找 PMF），S 曲线分析的前提（"有市场、有增长曲线"）不存在。先验证需求，再分析曲线。
