# 结构化题库

> 当用户选择"AI 给话题 → 随机挑战"时，AI 从本库按用户所选难度抽取题目。
> 六级结构：Level 1（判断题）→ Level 6（自行出题）
> 每级 ≥5 题。

---

## Level 1：判断题（基础认知）

**目标**：训练快速辨别真伪需求、区分"观点"与"事实"的能力。

| # | 题目 |
|:---|:---|
| 1 | "用户说想要这个功能"和"用户需要这个功能"是一回事吗？怎么判断？ |
| 2 | 一个功能上线后数据暴涨——这更多说明你做对了，还是之前的版本太差了？ |
| 3 | 老板说"我们要做 AI"——这是需求、方向、还是焦虑？三者的分界线在哪？ |
| 4 | "竞品做了所以我们也要做"——这个逻辑在什么时候成立，什么时候是陷阱？ |
| 5 | 用户的抱怨和用户的投诉是同一种信号吗？哪个更有价值？ |
| 6 | "数据驱动"和"数据盲从"的边界在哪？举一个你见过的数据盲从的例子。 |

---

## Level 2：选择题（方案权衡）

**目标**：训练在约束条件下做取舍，明确每个选择的代价。

| # | 题目 |
|:---|:---|
| 1 | 外包给第三方 vs 自建团队，你的判断框架是什么？最近一次用这个框架是什么时候？ |
| 2 | 先做广度（覆盖更多场景）还是先做深度（把一件事做透）？什么条件下选广度什么条件下选深度？ |
| 3 | 做一个"60 分的完整产品"还是"100 分的单点功能"——什么时候前者赢，什么时候后者赢？ |
| 4 | 产品优化：修老功能（存量用户受益）vs 做新功能（拉新用户）——怎么分配资源？ |
| 5 | 当一个功能 80% 的用户满意、20% 的用户强烈不满——删不删？你怎么判断？ |

---

## Level 3：问答题（逻辑分析）

**目标**：训练系统性归因和结构化推理，而不是"拍脑袋答"。

| # | 题目 |
|:---|:---|
| 1 | DAU 连续三周下滑，你怎么排查？请给出排查路径而不仅仅是"看数据"——先看什么，后看什么，为什么是这个顺序？ |
| 2 | 你做了一个"简化注册流程"的改动，注册转化率涨了 15%，但 7 日留存跌了 8%。你怎么归因？这个改动该回滚吗？ |
| 3 | 你的产品有三个完全不同画像的用户群（比如：小商家、连锁店管理者、总部分析师）。他们各自要用同一个后台——你会怎么设计？ |
| 4 | 一个功能你个人觉得很烂，但数据显示用户用得最多。你怎么处理这种"品味 vs 数据"的冲突？ |
| 5 | GMV 涨了 10%，但客单价跌了 5%，退货率涨了 2%。这个月是好是坏？你还需要什么信息才能判断？ |
| 6 | 老板给你定了一个看起来不可能完成的 OKR——你的反应路径是什么？第一个动作是做什么？ |

## Level 4：阅读理解（需求洞察）

**目标**：训练从表面需求读出隐藏需求和真实动机。

| # | 题目 |
|:---|:---|
| 1 | 老板说："我们要做一个类似抖音的推荐流。"——老板真正想要的，可能是哪三件不同的事？你会怎么追问？ |
| 2 | 用户反馈："你们的后台太复杂了，能不能简单一点？"——"简单"在这个场景里可能指什么？列出至少 4 种可能。 |
| 3 | 一个 B 端客户说："只要你们支持 API 对接我们就签。"签了之后发现对方的开发团队其实没有能力对接 API。下次遇到类似的话术，你会怎么提前预防？ |
| 4 | 客服反馈"用户投诉最多的就是加载速度"——你作为 PM 看到这句话，第一反应不是"优化性能"，而是追问哪三个问题？ |
| 5 | 销售团队说："竞品有这个功能，我们没有，所以单子丢了。"——这句话里有多少个待验证的假设？逐个拆开。 |

---

## Level 5：命题作文（完整产品设计）

**目标**：训练从零到一的产品化思维，覆盖问题定义→方案→SOP→规模化。

| # | 题目 |
|:---|:---|
| 1 | 为盲人设计一款智能家居产品。先定义盲人在家里的核心"麻烦"，再给出方案。关注：盲人的信息输入方式是什么？当前替代方案是什么？ |
| 2 | 如何降低外卖骑手的闯红灯率？先分解根因（是骑手不想等、平台算法逼的、还是红绿灯设计没考虑骑手场景？），再针对每个根因给方案。 |
| 3 | 设计一个"帮助小餐馆老板管理库存"的产品。前提：老板 45 岁、不会用电脑、每天在店里 12 小时、接受新工具的方式只有"隔壁老王用了好用"。 |
| 4 | 现有产品：知识付费 App。你的任务是设计一个"学习完成率提升方案"。注意区分：完课率低是因为内容差、用户忙、还是产品设计本身在阻碍坚持？ |
| 5 | 现有场景：医院门诊排号。排队 2 小时看病 5 分钟——从患者和医院两个视角，分别分析这个系统的约束和改进机会。 |

## Level 6：自行出题（元认知）

**目标**：训练从自己的日常工作和生活中发现问题并定义问题的能力。

| # | 题目 |
|:---|:---|
| 1 | 你最近一周用的某个产品（App/网站/实体物品都可），有没有让你感到特别不爽的一次体验？把这个不爽描述清楚：什么场景、什么操作、什么情绪？ |
| 2 | 你最近一周有没有做过一个"事后证明是错"的小决定？（比如：没看数据就改了功能、误判了一个需求的优先级）反推：在哪个节点如果有额外信息可以避免？ |
| 3 | 观察你所在组织的一个流程（报销、审批、上线、复盘都可以），找出其中"因为历史原因存在但没人质疑"的一个步骤。尝试挑战它——如果去掉会怎样？ |
| 4 | 你最近有没有跟同事/朋友产生过一个观点的分歧？把对方的论证用"最强版本"复述一遍（steel-manning），再反思：为什么你最初不同意？对方什么是有道理的？ |
| 5 | 选一个你正在做的需求或项目。写一条推特（280 字以内）向一个不熟悉你的行业的人解释它为什么重要。写完之后自己评价：这条推能不能让一个普通读者产生兴趣？ |
| 6 | 回顾你上个月的日历——时间花在最多的事情上是什么？如果下个月你只能做 3 件事，你会砍掉什么？用什么框架来判断"该砍什么"？ |
