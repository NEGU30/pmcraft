## 二、工具匹配标准

### 匹配的是"认知操作类型"，不是"应用领域"

两个步骤算同一工具，当且仅当：
1. 它们解决**同一种认知问题**——不是话题相同，而是思维动作同构。如"把模糊二元判断拆成独立可验证子命题""按某种内禀属性对使用场景做风险分级""分析交互双方隐含契约的类型并追问切换条件"
2. 核心机制相同——"怎么做"的底层逻辑一致
3. 适用领域不同——如果两场 sparring 话题领域相同（如都是 AI 产品定价），不算独立验证

### 反例

- Session A "按紧急度给用户需求分级" vs Session B "按容错率给使用场景分级" → 表面都是"分级"操作，但分级维度不同，需具体判断：如果 A 的分级方法论可以直接迁移到 B 且不需修改核心逻辑 → 同一工具；如果需要大幅调整 → 不同工具，分别登记

### 出场次数计数规则

- 同一 session 内多次使用同一工具 → 算 1 次出场
- 同一话题的多次 sparring（如 `_001` 和 `_002`）→ 分别计算（两次独立 sparring）
- 月度回顾只扫描近 30 天，但统计工具的总出场次数（读取 `_patterns.md` 中已有的历史出场记录 + 本月新出场）

## 三、状态转换规则

```
首次出现（1次）
  → 不登记。一次可能是偶然。

第二次出现（2次，不同领域）
  → 登记为 📝 待验证
  → 写入 🧰 工具复用登记

第三次出现（≥3次，含跨领域验证）
  → 升级为 🌿 候选框架
  → 从 🧰 移至 🌿 候选框架
  → 标注可复用性判断

后续每次出场
  → 更新出场列表
  → 更新"演化"描述
  → 若跨了新领域 → 增强可复用性判断

边界条件被触发
  → 标注 ⚠️ 边界修正
  → 在"已知边界"中追加新发现的失效条件
  → 框架本身不删除（边界更精确了，不是框架错了）

被确凿反例推翻
  → 降级为 ❌ 已失效
  → 保留记录（失效原因本身有价值）
  → 记录失效触发 session
```

## 四、盲区统计规则

从各场日志的"📊 支柱覆盖 + 🎯 诊断"表中提取：

- 支柱完全未涉及（权重 0%）→ 计入该支柱的"连续缺失"
- 深度未达 L4 的场次 → 计入 L4 达成率
- 万能回答被拦截次数 → 从幕后台词中推断（"没选的方向"中有无"可走但太泛"的标注）

趋势判定：
- 本月盲区场次 > 上月 → ⚠️ 恶化
- 本月盲区场次 < 上月 → ✅ 改善
- 持平 → ➡️ 持平

---

## 五、待验证假设去重规则

从各场日志的"待验证假设"段提取：

1. 提取所有 `- [ ] {假设} — 验证线索：{线索}` 条目
2. 按假设的语义相似度去重（两条假设本质相同但表述不同 → 合并，来源列表追加）
3. 如果某假设在后续 session 中已被验证（PM 在对话中确认或推翻）→ 标记 "✅ 已验证" 或 "❌ 已推翻"，从待验证池移除
4. 保留所有仍未关闭的假设，按来源场次数量降序排列
