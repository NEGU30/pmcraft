# 原型部署 (deploy-prototype)

## 概述

**本技能源码目录**：当前 SKILL.md 所在目录（如 `.../pmcraft-proto/skills/deploy-prototype/`），脚本与模板路径一律由此锚定解析，不依赖 cwd。

把一份已完成的原型部署到本机，起一个绑定全网卡（`0.0.0.0`）的本地服务，生成**同局域网可访问的分享链接**（形如 `http://<IP>:<端口>/`），发给同网络下的其他 PM 打开查看。

**默认部署源**：优先使用 `prototype/main/`（主分支快照，稳定且为最新交付版本）。如果 main/ 为空或不存在，fallback 到最新 E 版本目录。

本技能只做**附加部署层**，不改动原型内容，也不改写已生成的 `server.js`：

- **A 模式（纯静态原型，无 server.js）**：生成一个通用静态服务器 `server.js`，把 `index.html` + `pages/` 等静态文件通过局域网暴露出来。
- **B 模式（数据交互原型，已有 server.js，如问卷收集）**：复用现有 `server.js`，只补齐防火墙脚本、部署说明，并算出可分享的访问链接。

两类都统一使用 `mock/.server.pid` 记录 PID，使 CLAUDE.md 的「关闭服务」路由对二者一致生效。

**机械操作全部由 `scripts/deploy-prototype.js` 完成**：
- Node 自检、A/B 模式识别、基准端口读取
- 端口占用检测与冲突处理（+1 递增，上限 +10）
- 从 `{本技能源码目录}/templates/` 渲染部署文件（server.js / start.bat / close.bat / 防火墙脚本 / 部署说明.md，端口全局替换）
- 服务启动（Windows 分离式后台常驻）+ PID 写入
- IP 地址计算 + `http://localhost:{端口}/` 可达性校验

## 工作流程

### 第 0 步：Node 自检

脚本 `deploy-prototype.js` 内部已做 Node 自检（`node --version`），缺失时输出退出码 2 + 友好提示。LLM 无需单独自检，但若脚本返回 `error: "未检测到 Node.js"`，停止部署并回复：
> "本机没检测到 Node.js，部署需要它。到 https://nodejs.org 下载 LTS 版安装后（重开终端 `node --version` 能出版本号），再回来说'部署'。"

### 第 1 步：确定部署源

1. **如果** PM 已指定（"部署 E4" / "部署 working" / "部署 main"）→ 直接采用，跳至第 2 步。
2. **否则**（PM 未指定部署源）→ 按以下默认逻辑确定：
   - 检查 `prototype/main/` 是否存在且包含原型产物（`index.html` 或 `pages/` 目录或 `server.js`）→ 使用 `main/`，告知 PM："使用 prototype/main/（主分支快照）部署。"
   - 如果 main/ 不存在或为空 → 用 Glob 列出所有 `prototype/E*/`，取编号最大的 E 目录，告知 PM："main/ 为空，使用最新存档 {E{N}} 部署。"
   - 如果既无 main/ 也无任何 E 目录 → 检查 `prototype/working/`，存在则建议部署 working/。
3. **如果** PM 未指定但需要让 PM 选 → 用 Glob 列出 `prototype/working/`、`prototype/main/` 和所有 `prototype/E*/`，**调用 `AskUserQuestion` 工具**（如可用）让 PM 当场选（每次都问，不替 PM 记忆偏好）：
   - `question`: "部署哪一份原型？"
   - `header`: "部署源"
   - `options`: 动态生成——每个存在的源一个 option：
     - `{label: "main", description: "主分支快照，最新的稳定交付版本（推荐分享用）"}`
     - `{label: "E{最大编号}", description: "最新存档快照，稳定、可复现"}`
     - `{label: "其他 E 目录…", description: "..."}`（逐个列出）
     - `{label: "working", description: "当前改稿区，边改边看用，内容可能还在变"}`
   - `multiSelect`: false

   **备选（工具不可用时）**：> "部署哪一份原型？① main（主分支快照，推荐分享用）② E{最大编号}（最新存档快照）③ 其他 E 目录（存在几个列几个）④ working（当前改稿区）。回复编号即可。"
4. 校验所选源存在且含原型产物（脚本会校验）。

> 提示：分享给别人看，优先选 main/（主分支）或已存档的 E 目录（稳定不动）；working 适合自己边改边预览。

### 第 2 步：运行部署脚本

运行：
```bash
node "{本技能源码目录}/scripts/deploy-prototype.js" \
  --source="C:/项目/账号系统/1.0.0/prototype/main"
```

> **参数安全（Bash 注入防护）**：`--source` 部署源路径若由 PM 指定（如"部署 E4"→ LLM 拼接路径）或取自 PM 提供的路径表述（用户输入），构造 Bash 命令前必须剔除 `'` `"` `` ` `` `$` `;` `&` `|` `(` `)` 等 shell 元字符（或请 PM 确认实际路径）；路径值一律用双引号包裹后传入。含非法字符时以剔除后的路径提交并在结果展示中注明，不中断流程。

脚本自动完成：模式识别（A/B）→ 端口检测 → 模板渲染落盘 → 服务启动 → IP 计算 → 可达校验。

解析输出 JSON：
- `status: "ok"` → 按输出模板展示（使用 data 中的 `port`、`lan_ips`、`mode`、`local_url`、`admin_url` 等字段）
- `status: "interaction"` → 见第 3 步
- `status: "error"` → 按「边缘情况处理」表对应行处理（每行含 触发条件/处理方式/示例回复 三要素）；错误回复须包含 失败原因 + 处理指引 + 重试方式，示例话术以边缘表与错误示例为准，不得另造

展示前按部署源判断模板条件行：**如果** 部署源目录含 `annotations/`（标注层已生成）→ 附标注开关提示行；含 `demo/`（状态演示入口已生成）→ 附「演示」开关提示行；**否则** → 省略对应行（与 `{B 模式附：}` 条件行同理，话术逐字取自输出模板，不得改动）。

### 第 3 步：交互决策（端口被本原型自身占用时）

脚本返回 `{"status":"interaction","data":{"ask":"port_in_use",...}}` 时（本原型已在 {端口} 上运行），**调用 `AskUserQuestion` 工具**（如可用）询问 PM：

- `question`: 脚本返回的 `prompt`（"这个原型已经在 {端口} 上跑着了：{链接}。直接用这条链接分享，还是我帮你停掉重启一份？"）
- `header`: "端口占用"
- `options`:
  - `{label: "直接用现链接", description: "不重启，直接用已有服务"}`
  - `{label: "停掉重启", description: "停止现有服务后重新启动一份"}`
- `multiSelect`: false

**备选（工具不可用时）**：> "这个原型已经在 {端口} 上跑着了：{链接}。① 直接用这条链接分享 ② 我帮你停掉重启一份。回复编号即可。"

PM 选择后携带 `--answer=reuse` 或 `--answer=restart` 重调脚本：
```bash
node "{本技能源码目录}/scripts/deploy-prototype.js" --source="..." --answer=restart
```

### 第 4 步：防火墙引导 + 排障

- 技能**无法自动提权**运行 `netsh`。指示 PM：**右键 `allow-firewall.bat` →「以管理员身份运行」**，看到 `[OK] Inbound TCP port {端口} is now allowed` 即成功（首次一次即可）。
- 附排障清单（他人打不开时按序查）：
  1. `allow-firewall.bat` 没以管理员身份运行（最常见）。
  2. 两台设备不在同一网段（一个有线一个访客 Wi-Fi）。
  3. 公司 Wi-Fi 开了「客户端隔离」(AP isolation)，局域网内互访被禁——换网络或用真正的服务器部署。
  4. 本机服务是否还在跑（黑窗口是否还开着 / `mock/.server.pid` 是否在）。

## 禁止行为

1. **禁止修改原型内容** — 只新增部署基础设施文件，不动 `index.html` / `pages/` / 设计系统
2. **禁止改写已有 server.js** — B 模式一律复用现有服务器，避免破坏 build-prototype 生成的后端逻辑
3. **禁止静默换端口** — 端口冲突自动 +1 必须告知 PM（脚本返回 `port_bumped`）
4. **禁止伪造防火墙提权成功** — 生成 bat 交 PM 以管理员运行，不假装 netsh 成功
5. **禁止填写任何凭据** — 纯局域网静态服务不涉及外网访问与登录，不填任何凭据
6. **禁止静默跳过 Node 缺失** — 脚本检测失败即停并给安装指引
7. **禁止机器面向输出用中文** — `.bat` 的 `echo`/`title`、`server.js` 的 `console.log` 必须全英文 ASCII（中文 Windows 编码红线），中文只进 `部署说明.md` 与原型 HTML
8. **禁止自增输出模板字段** — 回复严格按输出模板，无内容的行省略

## 约束

1. **部署源默认优先 main/** — 不传部署源时，优先使用 `prototype/main/`（主分支快照），fallback 到最新 E 版本。PM 明确指定其他源时以指定为准。部署前告知 PM 实际使用的源。

## 错误示例

**错误 1：Node 缺失却继续起服务**
> 直接 `node server.js` 报 command not found 后装作没事。
> **问题**：违反禁止行为 6。**正确**：脚本返回错误即停，给 nodejs.org 指引。

**错误 2：改写了 B 模式的 server.js**
> 为了"加访问链接"去 patch 现有 server.js 的 listen。
> **问题**：违反禁止行为 2，可能破坏后端逻辑。**正确**：复用不动，链接由脚本计算。

**错误 3：替 PM 记住了上次选 working**
> "上次你部署的是 working，这次我也用 working。"
> **问题**：违反约束 1。**正确**：默认优先 main/，或每次让 PM 当场选。

**错误 4：伪造防火墙已放行**
> "已自动放行防火墙端口。"（实际 netsh 无管理员权限失败）
> **问题**：违反禁止行为 4，误导 PM。**正确**：如实说需右键以管理员运行 allow-firewall.bat。

## 边缘情况处理

| 场景 | 触发条件 | 处理方式 |
|:---|:---|:---|
| Node 未安装 | 脚本返回"未检测到 Node.js"（退出码 2） | 停止，给 nodejs.org LTS 安装指引 |
| 无任何原型产物 | 所选源下无 index.html/pages/ 也无 server.js | 脚本报错"部署源没有原型产物"，LLM 展示"还没有原型，先生成再部署" |
| main/ 存在且有内容 | PM 未指定源，main/ 可用 | 优先使用 main/，告知 PM |
| main/ 不存在或为空 | PM 未指定源，main/ 不可用 | fallback 到最新 E 目录，告知 PM |
| 端口被别的程序占用 | 脚本检测占用 PID 非本原型 | 脚本自动 +1 找空闲（上限 +10），返回 `port_bumped`，LLM 告知 PM；11 个全占则脚本报错 |
| 端口被本原型自己占用 | 占用 PID == 本源 mock/.server.pid | 脚本返回 `port_in_use` 交互，LLM 问 PM 复用现链接还是停掉重启 |
| 多网卡 | lanIPv4() 返回多个 | 全部列出，提示选同网段的 |
| 无可用 IP | 离线/无网卡 | 只给 localhost 链接，提示"当前没连局域网，联网后重跑" |
| AP 客户端隔离 | 同事仍打不开且排除前三项 | 说明是网络设备隔离，需换网络或真服务器部署 |
| 部署 E 目录或 main/ | 源是 E{N}/ 或 main/ | 确认摘要如实告知"将向 {源}/ 追加部署脚本，不改原型页面" |
| 部署源含标注层 | 部署源目录存在 `annotations/` | 输出模板附标注开关提示行（对程序员对齐 PRD 尤其有用）；不含则省略该行 |
| 部署源含状态演示入口 | 部署源目录存在 `demo/` | 输出模板附「演示」开关提示行（演示与评审更直观）；不含则省略该行 |
| 部署源路径含 shell 元字符（`'`、`"`、`$`、`;`、`&`、`|` 等） | PM 指定的部署目标/路径拼入 `--source` | 剔除元字符后以剔除版路径提交，不中断流程，并在结果展示中注明 |

## 评估测试用例

### 正向触发（7 条，均应激活本技能）
1. `部署`（有 main/ + E1/working）→ 默认使用 main/，运行脚本，起服务、报访问链接。
2. `分享给别人看` / `发到局域网` / `内网分享` → 同样进入部署流程，默认优先 main/。
3. A 模式源（无 server.js）→ 脚本生成通用 server.js，`curl localhost:{端口}/` 返回 200。
4. B 模式源（有 server.js）→ 脚本复用不改，读对端口，回复附 `/admin` 后台链接。
5. save-version 存档后追问"要部署分享吗？" → PM 同意 → 正常进入本技能。
6. 部署含标注层的源（部署源目录有 `annotations/`）→ 回复按输出模板附标注开关提示行（逐字输出，不改话术）。
7. 部署含状态演示入口的源（部署源目录有 `demo/`）→ 回复按输出模板附「演示」开关提示行（逐字输出，不改话术）。

### 负向触发（5 条，均不应激活本技能，应路由到别处）
1. PM 说 `保存` / `存档` / `交付` → 走 save-version，不进部署流程。
2. PM 说 `生成原型` / `做出来` → 走 build-prototype，不进部署流程。
3. PM 说 `规划页面` / `有哪些页面` → 走 plan-pages，不进部署流程。
4. PM 说 `设定风格` / `配色` → 走 set-style，不进部署流程。
5. PM 说 `关闭服务` → 由 CLAUDE.md「关闭服务」路由处理，不重新起部署流程。

### 边界（4 条）
1. Node 未装（脚本退出码 2）→ 停止并给 nodejs.org LTS 安装指引，不起服务；所选源无原型产物 → "还没有原型，先生成再部署"。
2. 端口 {基准} 被别的程序占用 → 脚本自动 +1（上限 +10）找空闲并返回 `port_bumped`；被本原型自己占用 → 返回 `port_in_use` 交互，LLM 问 PM 复用现链接还是停掉重启。
3. 多网卡 → 逐行列出所有 IP 并提示选同网段；无可用 IP → 只给 localhost 链接，提示联网后重跑。
4. 部署源无 `annotations/`（无标注层）→ 输出模板省略标注开关提示行；无 `demo/`（无状态演示入口）→ 省略「演示」开关提示行，其余条件行行为不变；含标注层/演示入口时则必须输出对应行。
