# 质检结果过滤规则（存量 vs 新增）

extend-html Phase 4 运行 check-quality 后，LLM 按本表对检出项做「存量问题 / 新增代码」二分过滤。核心原则：**存量问题记录不阻塞，新增代码偏离必须修复**。维度 7（标注层）与维度 8（演示层）：**首轮天然跳过**——首轮标注/演示面板在质检后生成（Phase 5 收尾衔接），质检时页面无注入标签；**后续轮启用**——页面已含注入标签（`annotations.css` / `annotations-runtime.js`、`demo-panel.css` / `demo-panel-runtime.js` 引用），脚本按既有逻辑检查，检出项按下方过滤表处理。

## 过滤规则表

| 检出项（维度） | 存量问题 | 新增代码 | 判定依据 |
|---------------|---------|---------|---------|
| 配色偏离色板（维度 3） | ✅ 记录不阻塞 | ❌ 必须修复为令牌色 | 存量低频色是页面既有视觉的一部分；新增色必须走 `var(--xxx)` 或页面一致字面值（R3） |
| 对比度不足（维度 3） | ✅ 记录不阻塞 | ⚠️ 记录并提示 | 存量配色不可改；新增文字/背景配对必须满足 4.5:1（可调令牌值） |
| 缺状态：加载/空/错误（维度 2） | ✅ 记录不阻塞 | ❌ 按 R6 补齐 | 存量页面可能本身无骨架屏；新增功能必须至少覆盖默认态 + 一种状态 |
| 存量交互不可点/快照级（维度 1） | ✅ 记录（标注"存量快照级"）不阻塞 | ❌ 必须可交互 | SPA 转换页动态 chunk 缺失导致交互快照级属预期，结构与样式仍 100% 保留 |
| 缺 label / touch 目标 / focus 可见（维度 1/5） | ✅ 记录不阻塞 | ❌ 必须修复 | 新表单元素必须带 label；新按钮 ≥36px；新交互元素有 focus-visible |
| 无横向溢出 / 文本溢出（维度 4） | ✅ 记录不阻塞 | ⚠️ 记录并提示 | 存量布局改动风险高，溢出修复涉及存量 CSS 时提示 PM 决策 |
| 反 AI 痕迹静态项（维度 6） | ✅ 记录不阻塞 | ⚠️ 记录并提示 | 存量 badge/emoji 属页面既有风格；新增代码按 anti-ai-flavor.md 规避 |
| 语义色错误（维度 3） | ⚠️ 记录不阻塞 | ⚠️ 记录并提示 | 错误提示必须用 danger 色、成功用 success 色 |
| 层级/重叠/排版（维度 4） | ✅ 记录不阻塞 | ❌ 必须修复 | 新增布局不得产生元素重叠 |
| 维度 7 标注层（4 项） | **首轮天然跳过 / 后续轮启用**：检出（assets / json / anchor / rules-covered）→ ⚠️ 记录并提示 | — | 首轮：质检时页面无标注注入标签，脚本不启用维度 7；后续轮：页面已含注入标签，检出即 MEDIUM 建议，处理 = 重新执行 annotate-prototype refresh（标注数据质量由 annotate 第九步自检兜底），不阻塞 |
| 维度 8 演示层（5 项） | **首轮天然跳过 / 后续轮启用**：检出（assets / json / order / anchor / coverage）→ ⚠️ 记录并提示 | — | 首轮：质检时页面无 demo 注入标签，脚本不启用维度 8；后续轮：页面已含注入标签，检出即 MEDIUM 建议，处理 = 重新执行演示面板生成（demo 数据从标注/页面清单重派生，幂等），不阻塞 |

## 报告口径

- **不阻塞项**：在对话中记录为"存量问题（记录不阻塞）"清单，不要求 PM 处理，不进入存档拦截。
- **必须修复项**：逐条展示并修复（Edit 精准片段），修复后重跑 check-quality 验证（重复此循环最多 2 次，仍失败 → 报告剩余项由 PM 决策）。
- **模板输出**：按 check-quality SKILL.md 的模板 A/B/C 输出，但**只对"新增代码偏离"执行模板 B 的"请确认"流程**；存量问题按"记录"口径汇总展示（不逐条追问）。

## 判定方法

1. **定位归属**：每条检出项带 `element`/`line` → 打开对应行，判断该元素/样式/脚本是否为本会话新增（对照 `.extend-html-history/` 快照 diff）。
2. **边界**：新增功能与存量区域交界处的检出项（如新增按钮借用存量 class 触发的样式冲突）→ 按"新增代码"从严处理，修复不得改动存量声明。
3. **无法归属** → 按"新增代码"从严处理（宁可多修，不放过新增偏离）。

## 明确不做

- 不执行 `--auto-fix`（会改写存量配色）。
- 不 spawn design-reviewer（独立设计评审面向标准流水线产物）。
- 标注衔接由 extend-html 自身编排：Phase 3 末（annotations/ 已存在 → refresh，质检前）/ Phase 5 收尾（annotations/ 不存在 → 补全数据文件后 build），质检不因标注检出阻塞（处理 = 重新 refresh）。
