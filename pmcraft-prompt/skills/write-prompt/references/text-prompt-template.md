# 文字提示词模板与技巧

本文档定义了文字类提示词的核心要素、按任务类型的模板骨架，以及高级技巧的速查参考。

---

## 一、文字提示词的核心要素（CRISPE 框架）

CRISPE 是处理复杂文本任务成熟的提示词框架之一（截至2026-07），通过六维度约束减少 AI 幻觉、提升输出精准度。

| 字段 | 全称 | 说明 | 示例 |
|------|------|------|------|
| **C** | Context 上下文 | 任务背景、目标受众、使用场景、领域知识 | "这是一家 B2B SaaS 公司的 Q1 财报数据，受众是公司管理层…" |
| **R** | Role 角色 | AI 应扮演的具体角色（含经验/特质） | "你是一名拥有 10 年经验的商业分析师，擅长从数据中提取战略洞察…" |
| **I** | Instruction 指令 | 要完成什么任务？输入→输出的清晰描述 | "分析以下销售数据，输出三个关键趋势及建议…" |
| **S** | Scenario 场景约束 | 长度、风格、格式、边界禁区 | "输出为 Markdown 表格，不超过 300 字，专业但不过于学术…" |
| **P** | Prompt 整合 | 整合以上+嵌入 Few-Shot 示例的最终指令 | "参考以下示例的格式和风格…" |
| **E** | Evaluation 评估 | 定义评估标准，让 AI 自检、方便迭代优化 | "评估标准：1. 每条趋势有数据支撑 2. 建议可落地执行…" |

**最小可行提示词** = C + R + I（知道背景、扮演谁、做什么）；
**高质量提示词** = CRISPE 六要素齐全。

> 框架原理、适用判断及与其他框架的对比见 `frameworks-guide.md` 第二节。发送前的逐字段检查清单见 `best-practices.md` 第一节。

## 二、按任务类型的模板骨架

### 1. 生成类（撰写文案、邮件、报告等）

```
# C — Context（上下文）
- 产品/主题：{什么产品、什么话题}
- 目标受众：{谁来读}
- 使用场景：{在什么情况下用，什么媒介发布}
- 品牌调性：{风格方向}

# R — Role（角色）
你是一名专业的{角色}，{经验/特质描述}。

# I — Instruction（指令）
撰写{内容类型}，突出{核心信息}。

# S — Scenario（场景约束）
1. 长度：{字数/段落要求}
2. 风格：{正式/轻松/专业/幽默等}
3. 必须包含：{关键信息点}
4. 禁止出现：{敏感词/不需要的内容}

# P — Prompt（整合与示例）
示例 1：
输入：{简短输入}
输出：{理想输出}

---

现在请撰写：{用户提供的具体输入}

# E — Evaluation（评估标准）
- {标准 1}
- {标准 2}
```

### 2. 分析类（数据解读、竞品分析、趋势判断等）

```
# C — Context（上下文）
- 数据来源：{什么数据，来自哪里}
- 业务背景：{为什么需要这次分析}
- 目标受众：{谁来读分析结果}

# R — Role（角色）
你是一名{领域}专家，擅长从{数据类型}中提取关键洞察。

# I — Instruction（指令）
分析以下内容，产出{输出类型}。
分析维度：
1. {维度一}
2. {维度二}
3. {维度三}

# S — Scenario（场景约束）
- 每个发现附带具体数据或逻辑支撑
- 输出格式：{表格/要点/分级报告}
- 请先拆解问题，再逐步分析，最后综合结论

# P — Prompt（整合）
输入数据：
{数据/材料}

# E — Evaluation（评估标准）
- {标准 1}
- {标准 2}
```

### 3. 编程类（代码生成、审查、优化等）

```
# C — Context（上下文）
- 项目类型：{Web应用/CLI工具/数据处理等}
- 已有技术栈：{框架/库/数据库}
- 代码风格偏好：{函数式/面向对象/简洁优先}

# R — Role（角色）
你是一名资深{语言/技术栈}开发工程师。

# I — Instruction（指令）
{写代码 / 审查代码 / 优化代码 / 写测试}，具体要求见下方。

# S — Scenario（场景约束）
1. {功能要求 1}
2. {功能要求 2}
3. 包含：注释 / 错误处理 / 类型标注（按需勾选）

# P — Prompt（整合与示例）
{示例输入代码片段 / 需求描述}
{期望的输出代码}

---

现在请处理：{用户输入}

# E — Evaluation（评估标准）
- {标准 1：如"代码通过所有测试用例"}
- {标准 2：如"时间复杂度不超过 O(n log n)"}
```

### 4. 翻译类

```
# C — Context（上下文）
- 内容领域：{技术文档 / 文学作品 / 商务邮件 / 日常对话}
- 目标读者：{谁会读译文}

# R — Role（角色）
你是一名专业翻译，精通{源语言}和{目标语言}。

# I — Instruction（指令）
将以下内容从{源语言}翻译为{目标语言}。

# S — Scenario（场景约束）
- 风格：{直译准确优先 / 意译流畅优先 / 文学性翻译}
- 术语表（如有）：
  | {源语言} | {目标语言} |
  |----------|------------|
  | X | Y |
- 特殊要求：{保留术语 / 本地化改写 / 注释翻译依据}

# P — Prompt（整合）
---
{待翻译内容}

# E — Evaluation（评估标准）
- {标准 1：如"专业术语翻译一致"}
- {标准 2：如"句式符合目标语言习惯"}
```

### 5. 对话/交互类（客服、咨询、教学等）

```
# C — Context（上下文）
- 对话场景：{在什么情况下发生对话}
- 用户类型：{和谁对话}

# R — Role（角色）
你是一名{角色}，{经验/特质描述}。

# I — Instruction（指令）
与{用户类型}进行对话，{对话目的}。

# S — Scenario（场景约束）
- 语气：{友好/专业/亲切/克制}
- 边界：永远不要{某些禁止行为}
- 知识范围：{你了解什么，不了解什么要诚实说}

# P — Prompt（整合与示例）
用户：{典型问题}
你：{理想回复}

# E — Evaluation（评估标准）
- {标准 1：如"回复准确且符合角色语气"}
- {标准 2：如"不确定时诚实告知而非编造"}
```

## 三、高级技巧速查

以下为速查表。每项技巧的详细说明、标准模板和正误对比见 `advanced-techniques.md`。

| 技巧 | 适用场景 | 关键写法 |
|------|----------|----------|
| **链式思考 (CoT)** | 数学、逻辑、复杂分析 | "请一步步思考，先拆解问题，再逐步推理，最后给出结论。" |
| **Few-Shot** | 风格控制、格式对齐 | 提供 2-3 个"输入→输出"示例，覆盖简单和复杂情况。详见 `few-shot-patterns.md` |
| **角色设定** | 专业任务、品牌一致 | "你是一名…" + 具体经验/特质描述 |
| **逆向工程** | 学习风格、复制效果 | "请分析以下范例的核心特征，然后生成同风格的输出。" |
| **预演失败** | 项目规划、决策评估 | "假设这个方案在 6 个月后失败了，分析最可能的失败原因。" |
| **双层解释** | 教学、概念传达 | "请用两个版本来解释：面向初学者的通俗版，面向专家的专业版。" |
| **分步迭代** | 复杂生成、编程 | 第一轮写骨架 → 第二轮加细节 → 第三轮润色 |
| **格式锁定** | 需要结构化输出 | 提供具体的输出模板（Markdown 表格/JSON 格式等） |

## 四、常见错误与纠正

完整版见 `best-practices.md`。以下为高频错误速查：

| 错误 | 问题 | 纠正 |
|------|------|------|
| 指令模糊 | "写个文案" | "写一篇 200 字产品文案，面向 25-35 岁职场女性，突出降噪和续航两个卖点。" |
| 缺上下文 | "优化这段代码" | 补充：项目类型、性能目标、接口约束 |
| 过度约束 | 同时要求"搞笑"+"严肃"+"500字"+"10个角色" | 减少到 2-3 个核心约束 |
| 忽略格式 | 不指定输出格式 | 明确要求：表格/列表/分段报告 |
| 无示例 | 风格全靠文字描述 | 给 1-2 个"输入→输出"示例 |
| 平台参数混用 | 不同平台参数互串 | 详见 `best-practices.md` 多平台注意事项速查表 |

### 4.1 高频错误示例详解

#### 示例 1：指令模糊 → 精准指令

**Issues:** I 字段只说了"干什么"，没说明输入格式、输出结构和成功标准。AI 只能猜测用户的真实意图。

❌ Before:
"写个文案"

✅ After:
"写一篇 200 字产品文案，面向 25-35 岁职场女性，突出降噪和续航两个卖点，生活化语气，带 emoji。"

#### 示例 2：缺上下文 → 充分上下文

**Issues:** C 字段完全缺失——AI 不知道这是什么项目、什么技术栈、什么性能目标，只能给出泛化建议。

❌ Before:
"优化这段代码"

✅ After:
"这是一个用户画像分析模块，处理 100 万条数据，当前数据库查询是瓶颈。优化目标：查询时间从 5 秒降到 1 秒以内，不改变现有接口。"

#### 示例 3：角色空壳 → 真实专家

**Issues:** R 字段笼统（"你是专家"），没有经验锚点和风格定义。AI 以通用模式输出，缺乏专业深度。

❌ Before:
"你是一名文案专家。写一篇产品介绍。"

✅ After:
"你是一名拥有 8 年 DTC 消费品牌经验的文案总监，擅长用消费者洞察驱动转化。风格：短句为主，每段不超过 3 行，用数据说话但不说教。请为 {产品} 写一篇电商详情页文案。"

> 完整 8 条错误的 Symptoms/Root Causes/Solutions/Example Fix 结构化分析见 `best-practices.md` 第三节。

## 五、快速诊断卡

当 AI 输出不理想时，按 CRISPE 顺序排查。完整调试指南见 `best-practices.md`：

1. **C — Context 是否充足？** → 背景、受众、场景给了吗？
2. **R — Role 是否明确？** → AI 知道自己"是谁"吗？
3. **I — Instruction 是否清晰？** → 能用一句话说清输入→输出吗？
4. **S — Scenario 约束是否到位？** → 长度、格式、风格、边界都给了吗？
5. **P — Prompt 示例是否到位？** → 有没有 2-3 个理想范例？
6. **E — Evaluation 标准是否明确？** → AI 怎么知道做得好不好？
7. **是否太复杂？** → 能否拆成多个简单步骤？
