# 提示词框架选择指南

本文档详解 prompt-writer 使用的提示词框架体系，帮助理解何时选用哪个框架、如何组合使用。

---

## 一、框架总览

| 框架 | 核心思想 | 复杂度 | 适用场景 |
|------|----------|--------|----------|
| **CRISPE** | 六维约束减少幻觉 | ⭐⭐⭐ | 复杂专业任务（文案、分析、咨询） |
| **OpenAI 六大原则** | 清晰沟通逻辑 | ⭐ | 简单通用任务（问答、总结、翻译） |
| **JSON 结构化** | 键值对强制结构化 | ⭐⭐⭐⭐ | 编程/API 对接、自动化流程 |
| **元认知推理** | 先推理后回答 | ⭐⭐⭐⭐⭐ | 高可靠性分析、决策、数学证明 |

**没有"最好"的框架，只有"最合适"的框架。** 选择取决于任务的复杂度、可靠性要求和可维护性需求。

---

## 二、CRISPE 框架（详细）

prompt-writer 的默认框架。通过六维度约束，减少 AI"幻觉"，提高输出的精准性和场景适配性。

### 六字段详解

| 字段 | 全称 | 核心问题 | 示例 |
|------|------|----------|------|
| **C** | Context 上下文 | 在什么背景下做？谁来读？在什么媒介上用？ | "这是一家 B2B SaaS 公司的 Q1 财报数据，受众是公司管理层，用于月度经营分析会…" |
| **R** | Role 角色 | AI 扮演谁？经验、特质、视角？ | "你是一名拥有 10 年经验的商业分析师，擅长从数据中提取战略洞察，沟通风格直击要点…" |
| **I** | Instruction 指令 | 要做什么？输入是什么？输出是什么？ | "分析以下销售数据，输出三个关键趋势及可执行的改进建议…" |
| **S** | Scenario 场景约束 | 长度、风格、格式、边界？什么不能做？ | "输出为 Markdown 表格，不超过 300 字，专业但不过于学术。不涉及任何客户隐私数据…" |
| **P** | Prompt 整合 | 整合以上 + 嵌入 Few-Shot 示例的最终指令 | "参考以下示例的格式和分析深度…" |
| **E** | Evaluation 评估 | 如何判断输出好坏？AI 自检的标准？ | "评估标准：1. 每条趋势有具体数据支撑 2. 建议可落地执行 3. 没有模糊推测…" |

### 为什么 CRISPE 有效

1. **Context 锚定背景** — 告诉 AI "你在什么环境里做事"，避免回答过于通用
2. **Role 锁定视角** — 角色决定语气、深度、取舍。同样的问题，"CEO 顾问"和"一线客服"的回答完全不同
3. **Instruction 明确路径** — 从输入到输出的清晰映射，减少 AI 的自由发挥空间
4. **Scenario 划定边界** — 约束不是限制创造力，而是把创造力引导到正确方向
5. **Prompt 嵌入示例** — 示例比语言描述更精准，一对好示例胜过三段说明
6. **Evaluation 闭环** — 让 AI 自己检查自己，减少人工后处理

### 适用判断

| 信号 | 建议 |
|------|------|
| 任务涉及 3+ 个约束维度 | ✅ 用 CRISPE |
| 输出质量要求高、不能出错 | ✅ 用 CRISPE |
| 有明确的受众和场景 | ✅ 用 CRISPE |
| 只是一句话问答 | ❌ 过度设计，用简化版 |
| 需要快速试错迭代 | ❌ 用 OpenAI 原则 |

> 按任务类型的 CRISPE 模板骨架见 `text-prompt-template.md` 第二节。发送前的逐字段自查清单见 `best-practices.md` 第一节。

## 三、OpenAI 六大原则（简化版）

当任务简单或需要快速迭代时，用这个轻量版。六大原则如下：

1. **写出清晰的指令** — 用具体描述替代模糊表达。❌ "写个文案" → ✅ "写一段 50 字的产品卖点文案，面向 25-35 岁职场女性"
2. **提供参考文本** — 给出相关资料、文档、数据作为知识库
3. **拆分复杂任务** — 分步骤、分模块处理："先分析用户需求，再给出解决方案，最后提供实施步骤"
4. **给模型思考时间** — 使用链式思考（CoT），让 AI 展示推理过程而不是直接跳到结论
5. **使用外部工具** — 结合代码执行、搜索等工具增强能力
6. **系统地测试变更** — 迭代测试，逐步优化提示词

### 与 CRISPE 的定位差异

| 维度 | CRISPE | OpenAI 六大原则 |
|------|--------|-----------------|
| 结构 | 固定六字段，按字段填充 | 原则导向，自由组合 |
| 上手难度 | 需要理解六个字段 | 零门槛 |
| 输出一致性 | 高（字段约束强） | 中（依赖用户经验） |
| 适合谁 | 需要稳定产出的专业场景 | 需要快速探索、轻量使用 |

**选择信号**：用户说"我先试试看，不一定对" → OpenAI 原则；用户说"这个要正式用，质量要稳定" → CRISPE。

## 四、JSON 结构化框架

用 JSON 键值对替代线性自然语言，强制结构化思维。

### 适用场景

- 编程/API 对接任务
- 多参数、多约束的复杂指令
- Agent 设计（状态维护、工作流）
- 需要程序化解析的输出

### 示例

```json
{
  "context": "电子商务平台的商品推荐系统，用户数据量 500 万",
  "role": "资深推荐算法工程师",
  "instruction": {
    "task": "优化商品推荐的多样性",
    "input": "当前推荐系统的点击率和转化率数据",
    "output": "升级方案，含算法选择和 A/B 测试设计"
  },
  "scenario": {
    "format": "技术方案文档",
    "constraints": "不改变现有数据管道接口",
    "length": "2000 字"
  },
  "evaluation": {
    "criteria": ["多样性指标提升 ≥10%", "点击率不下降", "方案可直接落地"]
  }
}
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 指令模块化，易于维护和复用 | 不适合简单对话任务 |
| 键名即语义，减少歧义 | 非技术用户上手成本高 |
| 易于程序化生成和解析 | 过度结构化可能压制创意 |

## 五、元认知推理框架

让 AI 在回答前进行系统性的自我推理和检查，提升答案可靠性。

### 五步流程

1. **分解 (Decompose)** — 将问题拆分为子问题
2. **解决 (Solve)** — 逐一处理，给出置信度
3. **验证 (Verify)** — 检查逻辑、事实、完整性、偏见
4. **综合 (Synthesize)** — 整合答案
5. **反思 (Reflect)** — 若置信度低，找出弱点重试

### 适用场景

- 高可靠性分析、决策任务
- 复杂推理、数学证明、法律分析
- 多步骤 Agent 工作流

### 不适用场景

- 简单问答或摘要任务（过度设计）
- 对延迟敏感的实时任务（推理步骤增加耗时）

## 六、框架选择决策树

```
开始
  │
  ├─ 是文生图任务吗？
  │   └─ 是 → 六层结构（详见 image-prompt-template.md）
  │
  └─ 是文字任务 →
      │
      ├─ 简单通用（问答/总结/翻译）→ OpenAI 六大原则（简化版）
      │
      ├─ 复杂专业（文案/分析/咨询）→ CRISPE 框架
      │
      ├─ 编程/API/自动化 → JSON 结构化 或 CRISPE + JSON
      │
      ├─ 高可靠性需求（分析/决策/数学）→ 元认知推理 或 CRISPE + CoT
      │
      └─ 不确定 → 默认 CRISPE，用户觉得重再降级
```

## 七、组合使用策略

| 场景 | 推荐组合 | 理由 |
|------|----------|------|
| 专业文案创作 | CRISPE + Few-Shot | 示例锁定风格，框架锁定结构 |
| 复杂数据分析 | CRISPE + 链式思考 (CoT) | CoT 提升推理可靠性 |
| AI 生图工作流 | 六层结构 + JSON 格式（可选） | 分层控制画面要素 |
| 高可靠性决策系统 | 元认知推理 + JSON 格式 | 推理过程可追溯，输出可解析 |
| 简单问答 | OpenAI 原则（简化版） | 够用不过度 |
| 编程任务 | CRISPE + JSON 结构化 | 字段约束 + 结构化输出 |
