# 提示词最佳实践与避坑指南

本文档收录提示词使用和管理的增效技巧、常见错误方案、调试指南。

---

## 一、CRISPE 检查清单

在发送提示词前，逐字段检查：

```
## C — Context（上下文）
- [ ] 任务背景已说明（为什么需要做？）
- [ ] 目标受众已明确（谁来读/用结果？）
- [ ] 使用场景已描述（在什么媒介/情况下用？）

## R — Role（角色）
- [ ] AI 的角色已指定（扮演谁？）
- [ ] 角色描述足够具体（有经验/特质，不是空壳标签）

## I — Instruction（指令）
- [ ] 输入格式已说明（AI 会收到什么样的内容？）
- [ ] 输出格式已指定（期望 AI 产出什么？什么结构？）
- [ ] 任务可验证（怎么判断完成得好不好？）

## S — Scenario（场景约束）
- [ ] 长度/字数有要求
- [ ] 风格/语调已指定
- [ ] 禁区/边界已明确（什么绝对不能出现？）

## P — Prompt（整合）
- [ ] Few-Shot 示例已附上（2-3 个）
- [ ] 示例覆盖简单和复杂两种情况
- [ ] 变量占位符用 {{变量名}} 标记清晰

## E — Evaluation（评估）
- [ ] 评估标准已写入提示词
- [ ] 标准具体可判断（不是"写得好"，而是"转化率>5%"）
```

> 框架深度解释与适用判断见 `frameworks-guide.md` 第二节。按任务类型的模板骨架见 `text-prompt-template.md` 第二节。

## 二、提示词生命周期管理

### 2.1 版本控制

**核心思想**：像管理代码一样管理提示词——版本记录、变更日志、回滚能力。

**命名规范**：

```
产品文案提示词_v1.md
产品文案提示词_v2.md
产品文案提示词_v3_正式版.md
```

**版本记录格式**：

```markdown
# 产品文案提示词

## 版本历史

### v1.0 (2026-01-15)
- 初始版本
- 框架：CRISPE

### v2.0 (2026-01-20)
- 增加 Few-Shot 示例（小红书风格）
- 优化 E 字段评估标准

### v3.0 (2026-01-25)
- 增加邮件营销变体
- 调整字数限制从 200 到 150
```

### 2.2 占位符设计

**目的**：让提示词可复用——替换变量即可适应不同场景，无需重写。

```
你是一名专业的 {{角色}}。

# C — Context
为 {{产品名称}} 撰写 {{内容类型}}。
目标受众：{{目标受众}}

# S — Scenario
字数：{{字数要求}}
风格：{{风格要求}}

使用时替换：
- {{角色}}：产品营销专家
- {{产品名称}}：智能降噪耳机
- {{内容类型}}：小红书种草文案
- {{目标受众}}：25-30 岁都市白领
- {{字数要求}}：100 字左右
- {{风格要求}}：生活化、有感染力
```

### 2.3 A/B 测试

**目的**：对比不同版本的提示词效果，选择最优。

**测试记录模板**：

```markdown
# A/B 测试记录

## 测试目标
生成小红书产品文案

## 版本 A（基础版）
```
你是一名营销专家。请为智能降噪耳机写一篇小红书文案，100 字左右。
```

## 版本 B（CRISPE + Few-Shot）
```
# C — Context
产品：智能降噪耳机。目标受众：25-30 岁都市白领。
# R — Role
你是一名擅长小红书文案的营销专家，深谙年轻化表达。
# I — Instruction
撰写一篇产品种草文案。
# S — Scenario
80-120 字，必须包含生活化场景和 emoji。
# P — Prompt
示例：[附 2 个同风格示例]
# E — Evaluation
文案需引发"想买"的感觉，而非硬广推销。
```

## 测试结果

| 版本 | 生成质量 | 风格匹配 | 可用率 | 备注 |
|------|---------|----------|--------|------|
| A | ⭐⭐⭐ | ⭐⭐ | 60% | 偏通用，风格不稳定 |
| B | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 95% | 风格统一，可直接发布 |

## 结论
采用版本 B。
```

## 三、常见错误与纠正

### 错误 1：指令模糊

**Symptoms:** AI 输出不符合预期，过于宽泛，方向性错误。

**Root Causes:** I（Instruction）字段只描述了"做什么"但没说"做到什么程度"。缺少输入→输出的明确映射、具体维度和成功标准。

**Solutions:**
1. 明确输入格式：AI 会收到什么？
2. 明确输出格式：期望 AI 产出什么？什么结构？
3. 补充具体维度：字数、风格、必须包含的关键点
4. 加入自检标准：E 字段让 AI 知道自己做得好不好

**Example Fix:**
❌ Before:
"写一篇关于环保的文章。"

✅ After:
"写一篇关于塑料污染的科普文章，面向高中生，800 字，包含：
1. 塑料污染的现状数据
2. 对海洋生态的影响
3. 个人可以采取的 3 个行动
用短段落和项目符号组织内容。"

---

### 错误 2：缺少上下文

**Symptoms:** AI 输出过于通用，不贴合实际场景，缺少领域特异性。

**Root Causes:** C（Context）字段缺失——没告诉 AI 任务背景、目标受众和使用场景。AI 只能给出泛化回答。

**Solutions:**
1. 补充任务背景：为什么需要做这个任务？
2. 明确目标受众：谁来读/用结果？
3. 描述使用场景：在什么媒介/情况下用？
4. 提供领域知识：有什么 AI 需要知道但不会自动知道的？

**Example Fix:**
❌ Before:
"优化这段代码。"

✅ After:
"这是一个用户画像分析模块，需要处理 100 万条用户数据，当前瓶颈在数据库查询。
优化目标：查询时间从 5 秒降到 1 秒以内，不改变现有接口。"

---

### 错误 3：过度约束

**Symptoms:** AI 输出生硬、矛盾，或无法同时满足所有要求。例如要求"搞笑"又要求"严肃"。

**Root Causes:** 同时施加 5+ 条互斥约束，AI 无法在冲突要求间找到平衡点。约束之间逻辑矛盾。

**Solutions:**
1. 减少到 2-3 个核心约束，其余放开
2. 检查约束之间是否逻辑冲突
3. 分步生成：先满足核心约束，再逐步叠加
4. 用正向指令替代负向指令（"要 X"而非"不要 Y"）

**Example Fix:**
❌ Before:
"写一个搞笑的故事，但要严肃认真，500 字，包含 10 个角色，每个角色都要有完整的背景故事，还要有教育意义…"

✅ After:
"写一个有幽默感的职场故事，2-3 个主要角色，800 字左右，主题是'新员工的成长'。"

---

### 错误 4：忽略输出格式

**Symptoms:** AI 输出格式不符合使用需求，需要大量手动后处理才能用。

**Root Causes:** I 或 S 字段未指定输出格式。AI 默认输出自然段落，而非用户实际需要的表格/JSON/列表等格式。

**Solutions:**
1. 明确指定输出格式（Markdown 表格 / JSON / 列表 / 分段报告）
2. 提供格式模板或示例
3. 在 P（Prompt）字段中直接给出格式骨架

**Example Fix:**
❌ Before:
"分析这几个产品的优缺点。"

✅ After:
"分析以下产品的优缺点，输出为 Markdown 表格：
| 产品 | 优点（3 个） | 缺点（2 个） | 推荐指数（1-5） |"

---

### 错误 5：忘记 Few-Shot 示例

**Symptoms:** AI 输出风格不稳定，每次结果差异大，偏离期望的语气或结构。

**Root Causes:** 只用语言文字描述风格要求，缺少具体的"输入→输出"范例。文字描述不如示例精准。

**Solutions:**
1. 提供 2-3 个理想范例（覆盖简单和复杂情况）
2. 示例必须包含"输入"和"期望输出"两部分
3. 示例中的语气、结构、深度应当与目标一致

**Example Fix:**
❌ Before:
"写产品评价，要客观真实。"

✅ After:
"写产品评价，要客观真实。

示例 1：
产品：无线耳机
评价：用了两周，音质不错，降噪有效，但续航短了点，每天都要充电。

示例 2：
产品：智能手表
评价：续航给力两周充一次，心率监测和医用设备比有差距。

现在请评价：{{产品名称}}"

---

### 错误 6：平台参数混用

**Symptoms:** 生成的提示词在目标平台无法正常工作——MJ 参数出现在 SD 里，空洞标签堆在 Nano Banana 里，DALL-E 里写 negative prompt。

**Root Causes:** 不熟悉目标平台的提示词语法，将 A 平台的参数格式直接复制到 B 平台。

**Solutions:**
1. 确认目标平台后，查阅对应平台的适配规则
2. 不混用跨平台参数

**Example Fix:**

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| SD 提示词里写 `--ar 16:9 --v 6` | SD 不需要这些参数，MJ 才需要 |
| Nano Banana 堆砌 `4k, masterpiece, trending on artstation` | NB 不推荐空洞质量词，描述具体即可 |
| DALL-E 提示词里加 `negative prompt: ...` | DALL-E 不需要 negative prompt |

> 详细平台适配规则见 `image-prompt-template.md` 第二节"按平台适配"。

---

### 错误 7：过度简化（幻觉风险）

**Symptoms:** AI 编造事实、给出自信但错误的结论、数据无来源、引用不存在的文献。

**Root Causes:** 提示词鼓励推测（"你认为未来会怎样"），未要求推理过程或引用来源。缺少 E 字段让 AI 自检。

**Solutions:**
1. 要求标注信息来源或置信度
2. 加入链式思考（CoT）指令：先拆解再推理
3. 明确边界："如果不确定，请说明而非猜测"
4. 要求提供推理过程而非仅给结论

**Example Fix:**
❌ Before:
"明年这个行业的市场规模会是多少？"

✅ After:
"基于现有数据，推演明年市场规模的可能范围。展示推理过程，标注每个推论的置信度（高/中/低）。如果不确定，请说明而非猜测。"

---

### 错误 8：角色空壳化

**Symptoms:** AI 输出了符合格式的内容，但缺乏专业性、深度或特定的视角——"听起来像 AI 写的"。

**Root Causes:** R（Role）字段过于笼统（"你是一名专家"），没有具体经验、特质和方法论锚定。角色描述空洞导致 AI 只能以通用模式输出。

**Solutions:**
1. 给角色加具体经验数值："拥有 10 年 B2B 产品营销经验"
2. 给角色加方法论偏好："擅长用 Jobs-to-be-Done 框架分析需求"
3. 给角色加输出风格："沟通风格直击要点，每页 PPT 不超过 3 条核心信息"

**Example Fix:**
❌ Before:
"你是一名营销专家。写一篇产品文案。"

✅ After:
"你是一名拥有 8 年 DTC 品牌营销经验的增长负责人，擅长用数据叙事和情感钩子驱动转化。你的文案风格简洁有力，每段不超过 3 行，善用短句制造节奏感。请为 {产品} 撰写发布文案。"

## 四、提示词调试技巧

当 AI 输出不符合预期时，按以下顺序排查：

| 问题 | 排查方向 | 修复方法 |
|------|----------|----------|
| 输出太简单 | I 字段不够具体？约束太少？ | 增加"请详细说明"，补充具体维度 |
| 输出太冗长 | S 字段缺少长度约束？ | 加"控制在 X 字以内" |
| 风格不对 | R 字段角色太模糊？P 缺少示例？ | 具体化角色特质，增加 2-3 个风格示例 |
| 格式不对 | I 字段未指定格式？ | 提供输出格式模板或 Markdown 示例 |
| 内容偏离主题 | C 字段背景缺失？I 指令模糊？ | 补充背景和明确的任务边界 |
| 总是出错 | 任务太复杂？ | 拆分成多个简单步骤，逐步执行 |
| 每次结果不一致 | 缺少 E 字段评估标准？ | 加入明确的评估标准让 AI 自检 |

### 4.1 调试工作流

当问题不在上表中、或排查后仍未解决时，按以下五步流程系统诊断：

**Step 1: 确定问题**
- 具体哪里不符合预期？是风格、格式、内容深度、还是逻辑问题？
- 与预期的差距有多大？用一句话描述：我希望 X，但实际得到了 Y。

**Step 2: 定位根源**
- 按 CRISPE 字段逐一排查（见上方调试表）
- 是对应字段缺失、模糊、还是冲突？
- 是提示词本身的问题，还是任务本身过于复杂？

**Step 3: 制定修复假设**
- 补全缺失字段（C/R/I/S/P/E 逐个检查）
- 细化模糊描述（具体字数、具体格式、具体风格词）
- 增加 Few-Shot 示例（至少 2 个）
- 拆分复杂任务（分步生成而非一步到位）

**Step 4: 实施修复**
- 更新提示词对应字段
- 用 2-3 个不同输入进行测试
- 记录修改内容和效果

**Step 5: 验证**
- 现在符合预期了吗？
- 对不同类型的输入都稳定吗？
- 是否引入了新问题？

## 五、多平台注意事项速查

> 平台/参数说明截至 2026-07 校验（模型迭代后以官方最新为准）。
> 各平台详细适配指令（参数模板、正负词示例、禁用规则）见 `image-prompt-template.md` 第二节"按平台适配"。

| 平台 | 提示词风格 | 需要负面词 | 额外参数 | 特别注意 |
|------|-----------|-----------|----------|----------|
| **ChatGPT/Claude** | 自然语言、结构化 | 不需要 | 无 | 对话式迭代，重视角色设定 |
| **Midjourney** | 自然语言+参数 | 可用 `--no` 排除 | `--ar` `--v` `--style` 等 | 对风格词敏感，宽高比用参数 |
| **Stable Diffusion** | 逗号分隔标签 | 必须（标准 negative） | 无（通过 WebUI 配置） | 权重写法 `(keyword:1.2)` |
| **DALL-E 3** | 自然语言 | 不需要 | 无 | 内容过滤严格，不准生图的人物/品牌 |
| **ChatGPT 生图** | 自然语言对话式 | 不需要 | 无 | 支持多轮迭代修改，文字渲染强 |
| **Nano Banana Pro** | 主体+动作+场景+构图+风格 | 不需要 | 无（分辨率/宽高比在 UI 选） | 支持 14 张参考图，不堆砌空洞标签 |
| **即梦** | 主体+细节+风格+环境+技术参数，中文优先 | 建议加（畸形、结构错乱、水印等） | 权重 `(词:1.2)` 等 | 中文文字渲染突出，4.0 大白话也能出好图 |
| **可灵** | 主体+动作+场景+风格，英文优先 | 建议加（50-100 token） | 无（分辨率通过面板设置） | 禁写`高清``4K`等分辨率词，禁抽象词，中式风格关键词敏感 |

### 6.1 评估框架模板

用于系统化测试提示词效果，建议在正式上线前用以下 5 类用例检验：

| 用例 | 输入 | 期望输出 | 成功标准 |
|------|------|----------|----------|
| 正常输入 | {标准、完整的输入} | {具体、详细的理想输出} | {可度量的判定标准} |
| 模糊输入 | {故意不完整或歧义的输入} | {AI 应追问澄清} | {追问了关键信息缺失点} |
| 边缘输入 | {极端或特殊的输入} | {AI 应合理处理} | {未崩溃或编造，给出了合理回应} |
| 错误输入 | {无效或格式错误的输入} | {AI 应报错并给出指引} | {错误信息清晰，给出了正确输入示例} |
| 回归测试 | {之前出错的输入} | {AI 现在应正确处理} | {之前的 bug 不再出现} |

> 每个用例至少测试 3 次取平均，确认一致性后再上线提示词。

## 七、核心心法

**写提示词的本质是思维工程。** 你定义问题的清晰度，直接决定了 AI 发挥的上限。

- 不要死记硬背模板——锻炼将模糊需求拆解为可执行指令的能力
- 把提示词当作可迭代的产品——持续测试、对比、优化
- 建立自己的提示词库——好的提示词是资产，应该复用和传承
- 不同平台有不同的"方言"——学会翻译，而非一套格式到处用

## 九、问题速查表

当发现问题时，快速定位修复方向：

| 问题表现 | 核心原因 | 快速修复 |
|----------|----------|----------|
| 输出太宽泛 | I 字段不够具体 | 补充输入→输出的明确映射 + 具体维度 |
| 风格不对 | R 字段角色模糊 | 具体化角色特质 + 2-3 个风格示例 |
| 格式不对 | I/S 缺少格式约束 | 提供输出格式模板或 Markdown 示例 |
| 内容偏离主题 | C 字段背景缺失 | 补充业务背景、受众和使用场景 |
| 每次结果不一致 | 缺少 E 字段评估标准 | 加入评估标准让 AI 自检 |
| 平台参数报错 | 混用其他平台参数 | 查阅 `image-prompt-template.md` 第二节 |
| 画面主体混杂 | 主体描述过于宽泛 | 确定唯一核心主体，锁定 3 个外观特征 |
| 风格词冲突 | 多个风格词互相矛盾 | 选一个主导风格，其余作为点缀 |
| AI 编造事实 | 提示词鼓励推测 | 加上 CoT 指令 + 要求标注置信度 |
| 输出像 AI 写的 | 角色太笼统 | 给角色加经验数值 + 方法论 + 输出风格 |
