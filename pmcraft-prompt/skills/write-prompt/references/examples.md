# 正误示例

本文档收录 prompt-writer 的正确交互场景与常见错误的结构化分析。示例采用 ❌ Before → Issues 诊断 → ✅ After 三层格式。

---

## 正确示例

### 场景 1：文字类，附带描述

```
用户：帮我写一个文字提示词，用来分析用户满意度调查数据，输出要点总结和改进建议

AI：好的，这是一个分析类文字提示词。先确认一下——
    这个分析的受众是谁？是给管理层看的高层摘要，还是给执行团队看的详细报告？
```

**预期**：AI 正确识别为文字-分析类，从追问受众开始，逐轮澄清。

---

### 场景 2：文生图，无详细描述

```
用户：帮我写一个文生图 prompt

AI：好的，你想生成什么类型的图？先说说画面主体——
    核心是谁或什么？人物、场景、还是物体？
```

**预期**：AI 展示场景选择，用户选文生图后，从主体开始逐轮追问。

---

### 场景 3：用户有参考示例

```
用户：帮我写产品文案的提示词，我之前有一个写得不错的你可以参考：（附示例）

AI：好的。参考你的示例，我提取了几个特征：生活化场景+核心卖点+emoji收尾。
    这次的新产品是什么？面向什么人群？
```

**预期**：AI 在阶段 3 使用用户示例作为 Few-Shot，而非构建假设示例。

---

### 场景 4：完整交互流程（端到端交付）

```
用户：帮我写一个文字提示词

AI：[展示文字/文生图选择菜单]
用户：1

AI：[第一轮追问 C-Context]
用户：我们公司新出了一款智能水杯，要在小红书发种草文案

AI：[第二轮追问 R-Role]
用户：扮演生活方式博主吧

AI：[第三轮追问 I-Instruction，用户确认为生成类+100字+轻松风格]

AI：[第四轮追问 S-Scenario]
用户：要有 emoji，不要太营销味

AI：[第五轮追问 P+E]
用户：没有示例。评估标准就是读起来像真人的分享，不是广告。

AI：[阶段 1A 结束确认摘要]

AI：[阶段 2 框架选择 — 推荐 CRISPE、说明理由，用户确认]

AI：[阶段 3 Few-Shot — AI 构建 2 个小红书风格假设示例，用户确认]

AI：[阶段 4 生成 + 阶段 5 输出四部分完整提示词包]

AI：[用户确认无误 → 进入 5A 保存流程 → 生成文件名"智能水杯种草文案_文字_20260623_E1.md"→ 写入 → 保存确认]
```

**预期**：完整走完 6 阶段 + 5A 保存，每个阶段都产生可见输出。

## 错误示例

### 错误 1：一次性问完所有维度

**Symptoms:** 用户被大量问题淹没，回答质量低，只回复最后 1-2 个问题或直接放弃。

❌ Before:
```
AI：好的。请告诉我：核心任务是什么？AI 扮演什么角色？
    输出给谁看？要多长？什么风格？有没有参考示例？用什么平台？
```

**Issues:** 一次抛出 7 个问题，用户认知过载，无法高质量逐一回答。违反了追问规则第 1 条"每轮只输出 1-2 个问题"。

✅ After:
```
AI：先聊聊背景——这个任务在什么业务或项目背景下产生？输出最终给谁看？
（等待用户回复后再问下一个问题）
```

---

### 错误 2：用户说"不知道"就直接放弃

**Symptoms:** 用户卡在某个维度不知如何选择，AI 不提供帮助，交互中断。

❌ Before:
```
用户：我不知道什么风格好

AI：好的，那你随便选一个吧。
```

**Issues:** 用户说"不知道"是求助信号，AI 应该发挥专家价值——提供推荐方向并解释理由。违反了追问规则第 5 条。

✅ After:
```
用户：我不知道什么风格好

AI：你描述的主体偏向科技产品，一般用"写实/照片级"或"3D 渲染"风格效果不错——
前者突出产品质感，后者适合展示功能细节。你看更喜欢哪个方向？
```

---

### 错误 3：忽略平台差异

**Symptoms:** 生成的提示词在目标平台无法正常工作，参数报错或效果不符。

❌ Before:
```
用户：帮我写 SD 的文生图 prompt

AI（输出）：A cyberpunk warrior standing in the rain, --ar 16:9 --v 6
```

**Issues:** `--ar` 和 `--v` 是 Midjourney 的参数，SD 不需要也不能用。违反了平台适配规则。

✅ After:
```
AI（输出）：
Positive: cyberpunk warrior, standing in rain, neon lights, detailed armor, photorealistic
Negative: lowres, bad anatomy, bad hands, text, error, cropped, worst quality, jpeg artifacts
```

---

### 错误 4：输出不完整

**Symptoms:** 只给了提示词正文，遗漏使用说明、参数说明、变体建议，用户不知道怎么用。

❌ Before:
```
用户确认后，AI 只输出：你是一名文案，写一篇 XXX 的文案。完毕。
```

**Issues:** 缺少四部分中的三部分（使用说明、参数说明、变体建议），且未进入保存流程。违反了阶段 5 的输出规范。

✅ After:
```
严格按照阶段 5 的四部分结构完整输出：📝 完整提示词 + 📖 使用说明 + ⚙️ 参数说明 + 🔄 变体建议。
确认后进入 5A 保存流程。
```

## 评价测试用例

### 正向触发（6 条）

1. **用户说"帮我写一个文字提示词，用来分析销售数据"** — 预期：识别为文字-分析类，从 C（Context）追问开始，逐轮完成 6 阶段流程，最终输出四部分+保存。
2. **用户说"帮我写一个文生图 prompt"** — 预期：识别为文生图场景，从主体开始逐轮追问，完成全部阶段。
3. **用户说"帮我写个 prompt"（无任何上下文）** — 预期：展示文字/文生图选择菜单。
4. **用户在追问中提供了完整信息**（任务、受众、格式、示例齐全）— 预期：AI 只追问缺失维度，已明确的跳过。
5. **用户有参考示例** — 预期：AI 在阶段 3 使用用户示例作为 Few-Shot，而非构建假设示例。
6. **用户确认并保存** — 预期：输出完整四部分→用户确认→进入保存（5A）→确定目录→生成文件名→确认→Write→保存确认。

### 负向触发（5 条）

1. **用户需求超出支持范围**（如"帮我写个视频生成 prompt"）— 预期：提示当前不支持，给出后续期待。
2. **用户连续回答 3 次"不知道"** — 预期：AI 转为推荐模式，给出 2-3 个推荐方向并标注"AI 推测"。
3. **阶段 1 追问超 10 轮** — 预期：总结已有信息，剩余标注"默认填充，后续可调整"，进入阶段 2。
4. **用户中途说"退出"** — 预期：确认是否放弃，告知当前进度。
5. **用户提供的示例与任务明显不匹配** — 预期：指出不匹配点，询问用户意图，不直接使用。

### 边界查询（4 条）

1. **用户描述极简**（如"帮我写个 prompt，要好看的"）— 预期：引导用户逐步澄清，不直接猜。
2. **用户需求横跨两个场景**（如"帮我写个 prompt，用来写产品文案还要配图"）— 预期：识别为两个独立任务，建议先做一个再做另一个。
3. **用户指定了不常用的生图平台**（如 ComfyUI、Fooocus）— 预期：按通用格式生成 + 告知具体参数需用户自行适配。
4. **用户要求生成后直接保存到文件** — 预期：必须经过确认环节，不跳过确认直接保存。确认后进入 5A 流程：询问目录→生成文件名并展示→确认→写入。
