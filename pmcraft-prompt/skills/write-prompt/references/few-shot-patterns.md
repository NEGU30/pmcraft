# Few-Shot（少样本）提示模式指南

Few-Shot 是提示词工程中最有效的技术之一——通过提供示例帮助 AI 理解任务期望。本文档定义 Few-Shot 的类型、格式模板，以及如何在 prompt-writer 流程中正确使用。

---

## 一、为什么 Few-Shot 有效

| 作用 | 说明 |
|------|------|
| **传递期望** | 示例比语言描述更精准——展示"想要什么"比说"想要什么"更有效 |
| **建立模式** | 帮 AI 识别输入输出的对应关系，减少猜测 |
| **消除歧义** | 通过具体案例消除措辞造成的理解偏差 |
| **稳定输出** | 有示例的提示词输出风格更一致、格式更规范 |

**数据参考**：2-3 个高质量示例通常能显著提升输出质量；但超过 5 个后边际收益递减，且大量占用 token。

---

## 二、Few-Shot 的三种类型

### 1. 正样本示例（Positive Examples）

展示**正确**的输入输出对应关系。大多数任务的首选。

```
示例 1：
输入："这个产品太棒了，我很喜欢！"
输出：积极

示例 2：
输入："服务态度很差，不会再来。"
输出：消极

示例 3：
输入："价格还可以，质量一般。"
输出：中性

---

现在请判断以下输入的情感：
输入："物流太慢了，包装也破了。"
```

### 2. 负样本示例（Negative Examples）

展示**错误**的示例，说明"不要什么"。需要明确边界时使用。

```
❌ 错误示例：
输入："iPhone 15"
输出："这是一个手机。"（过于简单，没有价值）

✅ 正确示例：
输入："iPhone 15"
输出："iPhone 15 采用钛金属设计，A17 Pro 芯片，6.1 英寸超视网膜 XDR 显示屏，USB-C 接口。"（详细、具体）

---

现在请为以下产品写描述：
产品："{{产品名称}}"
```

### 3. 边缘情况示例（Edge Cases）

展示**特殊、极端、异常**情况的处理方式。覆盖任务的关键边缘场景。

```
常规情况：
输入："什么时候发货？"
输出："您的订单将在 24 小时内发货，发货后会通知您。"

边缘情况：
输入："我等了一周还没发货！退款！"
输出："非常抱歉给您带来不便。我立即查询您的订单状态。如果发货延迟，可以为您加急处理或办理退款。您希望怎么处理？"
```

## 三、Few-Shot 示例设计原则

| 原则 | 说明 | 正误 |
|------|------|------|
| **真实性** | 示例应来自真实场景或贴合真实场景，而非脱离实际的虚构 | ✅ 用真实的用户反馈案例 ❌ 编一个没人会问的问题 |
| **代表性** | 示例应覆盖任务的主要类型和难度层级 | ✅ 包含简单+复杂+边缘三种 |
| **清晰性** | 输入输出对应关系一目了然，"输入：""输出："明确标注 | ✅ 标签清晰 ❌ 混在一起 |
| **数量适中** | 2-5 个最佳——太少不够，太多冗余且浪费 token | ✅ 3 个高质量示例 ❌ 10 个近似示例 |
| **多样性** | 示例之间有差异，覆盖不同角度和风格 | ✅ 覆盖不同用户类型、不同场景 ❌ 3 个示例实质上一样 |

## 四、对话中的 Few-Shot 处理流程

prompt-writer 的 Few-Shot 设计在阶段 3 完成，流程如下：

### Step 1：优先征求用户提供的真实示例

**推荐话术**：

- "有没有类似的示例可以给我参考？**真实的使用场景**会更好，这样我能更准确地理解你的需求。"
- "可以给我一对理想的输入输出示例吗？比如你会给 AI 什么样的输入，希望它给你什么样的输出？"

**为什么优先真实示例**：
- ✅ 贴合用户的实际使用场景
- ✅ 包含领域特定知识和语境
- ✅ 减少 AI 猜测和假设

### Step 2：审查示例完整性

- 完整的示例 = **输入 + 理想输出**。二者缺一不可
- 只有输入没有输出 → 请用户补充输出，或 AI 基于理解构建输出并请用户确认
- 只有输出没有输入 → 请用户补充输入，或 AI 反向构建并确认

### Step 3：构建假设示例（用户无示例时）

1. 基于阶段 1 收集的信息，构建 2-3 个贴合用户场景的示例
2. 用 `[AI 构建]` 明确标注，让用户知道这不是真实案例
3. 覆盖简单和复杂两种情况
4. **必须请用户确认**：不确认不得进入下一阶段

### Step 4：验证和迭代

- "这些示例是否符合你的实际使用场景？"
- "有没有遗漏的重要情况？"
- "输出的格式/风格/深度是你想要的吗？"

## 五、格式模板

### 模板 1：简单任务（分类、问答）

```
## 示例

**示例 1：**
输入：[具体输入]
输出：[期望输出]

**示例 2：**
输入：[具体输入]
输出：[期望输出]

**示例 3：**
输入：[具体输入]
输出：[期望输出]

---

现在请根据以上示例，处理：
输入：{{用户实际输入}}
```

### 模板 2：结构化任务（翻译、摘要、改写）

```
## 示例

| 原文 | 目标输出 |
|------|----------|
| [输入示例 1] | [输出示例 1] |
| [输入示例 2] | [输出示例 2] |
| [输入示例 3] | [输出示例 3] |

---

现在请处理：
原文：{{用户实际输入}}
```

### 模板 3：复杂任务（分析、生成）

```
## 参考示例

**案例 1：**
- 任务：[任务描述]
- 输入：[输入内容]
- 分析过程：[推理过程]
- 输出：[最终输出]

**案例 2：**
- 任务：[任务描述]
- 输入：[输入内容]
- 分析过程：[推理过程]
- 输出：[最终输出]

---

现在请处理：
任务：{{用户任务描述}}
输入：{{用户实际输入}}
分析过程：
输出：
```

## 六、常见错误

| 错误 | 问题 | 改进 |
|------|------|------|
| 示例虚构 | 与真实场景偏差大 | 使用真实案例，或明确标注 `[AI 构建]` |
| 示例单一 | 只展示一种情况 | 提供简单+复杂+边缘三种 |
| 输入输出对应模糊 | 关系不清晰，AI 难学习 | 用"输入："、"输出："明确标注 |
| 数量过多 | 占用大量 token，效果递减 | 2-5 个高质量示例即可 |
| 示例不准确 | 传达错误期望 | 与用户确认示例后再写入提示词 |
| 缺边缘情况 | AI 无法处理特殊输入 | 补充异常/极端情况的示例 |

## 七、文生图的 Few-Shot

文生图场景的 Few-Shot 与文字类不同——通常不是"输入→输出"，而是**风格片段**。

### 处理方式

- 若用户有参考图 → 将参考图的风格特征转化为文字描述，作为风格锚点
- 若用户无参考 → 根据主体和风格方向，构建 1-2 个画面描述片段
- 风格片段不是完整 prompt，而是**对齐风格理解的参考文本**

### 示例

```
风格参考片段：

"一位赛博朋克武士在霓虹雨中行走，冷蓝色调侧光，中景低角度仰拍，超写实胶片质感"

如果你想要的风格比这个更暗黑/更明亮/更写实/更动漫，告诉我，我调整。
```

## 八、Few-Shot 与其他技术的组合

| 组合 | 效果 | 适用场景 |
|------|------|----------|
| Few-Shot + CRISPE | 框架锁定结构，示例锁定风格 | 专业文案、正式报告 |
| Few-Shot + CoT | 示例中展示推理链，AI 模仿推理过程 | 数学、逻辑分析 |
| Few-Shot + 角色设定 | 示例语气统一角色风格 | 客服、咨询、教学 |
| Few-Shot + 六层结构 | 示例对齐画面风格，结构对齐要素控制 | AI 生图 |

---

## 九、快速参考

| Few-Shot 类型 | 适用场景 | 数量 | 来源优先级 |
|---------------|----------|------|-----------|
| 正样本 | 大多数任务 | 2-5 个 | 1. 用户提供 2. AI 构建 |
| 负样本 | 需要明确边界时 | 1-2 个 | 1. 用户提供 |
| 边缘情况 | 处理特殊输入时 | 1-3 个 | 1. 用户提供 2. AI 构建 |
| 风格片段（文生图） | 对齐画面风格 | 1-2 个 | 1. 用户参考图 2. AI 构建 |
