# 高级提示词技巧

本文档收录超越基础框架的进阶策略和特定场景优化技巧。每项技巧包含：核心思想、适用场景、标准模板和正误对比。

---

## 一、基础技巧深化

### 1. 正向指令原则

**核心思想**：给 AI 一个清晰的目标，而不是一个雷区。"要什么" > "不要什么"。

**为什么有效**：正向指令告诉 AI "往哪走"，负向指令只说"别去哪里"。AI 需要明确的方向，而非单纯的边界限制。

**正误对比**：

| ❌ 负向 | ✅ 正向 |
|---------|---------|
| "语气别太随意。" | "请使用正式、学术的语调写作。" |
| "不要写太长。" | "请用简洁的语言，控制在 200 字以内。" |
| "别用太多专业术语。" | "用通俗易懂的语言，适合非专业读者理解。" |

**最佳实践**：主要指令用正向，边界控制用负向。

```
任务：[明确的正向目标]

约束：
- [正向约束1：要什么样的风格/长度/格式]
- [负向约束1，用于明确禁区]
```

---

### 2. 细节与上下文原则

**核心思想**：AI 不知道你的项目背景。提供所有重要的细节和上下文，假设 AI 对你的情况一无所知。

**必须包含的上下文要素**：

| 要素 | 说明 | CRISPE 对应字段 |
|------|------|-----------------|
| 任务背景 | 为什么需要做这个任务？ | C — Context |
| 目标受众 | 谁会看到/使用结果？ | C — Context |
| 使用场景 | 结果在什么情况下被使用？ | C — Context |
| 已有信息 | 之前做过什么？有什么参考？ | P — Prompt |

**正误对比**：

❌
```
"分析一下这个。"
```

✅
```
"这是一份用户满意度调查数据。请总结关键发现，重点关注：
1. 用户抱怨最多的 3 个问题
2. 不同用户群体的满意度差异
3. 与去年相比的变化趋势
用项目符号列表展示，每个发现附带具体数据支持。"
```

## 二、进阶策略技巧

### 3. 链式思考（Chain of Thought, CoT）

**核心思想**：要求 AI 展示推理过程，大幅提升复杂问题的准确率。

**魔法咒语**：
- "Let's think step by step."
- "请先分析，再给出结论。"
- "请拆解问题，逐个子问题处理，最后综合。"

**适用场景**：数学计算、逻辑推理、复杂分析、多步骤问题。

**标准模板**：

```
# 任务
[任务描述]

# 要求
请使用链式思考方法完成这个任务：

1. **问题分解**：将这个问题拆解为几个子问题
2. **逐步分析**：对每个子问题进行详细分析
3. **综合结论**：基于分析得出最终结论

请清晰展示你的思考过程，不要直接跳到结论。
```

**示例**：

```
问题：一个农场有鸡和兔子共 50 只，腿共 140 条。鸡和兔子各多少？

请一步步思考：
1. 设鸡 x 只，兔子 y 只，列方程组
2. 解方程组
3. 验证答案是否符合题意
```

### 4. 逆向工程技巧

**核心思想**：把优秀的成品给 AI，让它反推生成这个结果的提示词。

**使用场景**：学习某种风格、复制成功案例、理解优秀作品的底层逻辑。

**标准模板**：

```
# 任务
这是我想要的成品范例。

[范例内容：文章/图片描述/代码等]

请你：
1. 倒推一个提示词，让我以后能稳定生成同风格的内容
2. 分析这个范例的核心特征和结构
3. 给出可复用的提示词模板
```

**应用示例**：

```
这是一篇爆款小红书文案：
[文案内容]

请分析这篇文案的写作技巧，并帮我写一个提示词模板，让我以后能写出类似风格的文案。
```

### 5. 双层解释法

**核心思想**：用两种方式解释同一个概念，对照学习，理解更透彻。

**标准模板**：

```
请帮我解释【概念名称】。

**版本 1：初学者版本**
面向：[具体人群，如"完全不了解的中学生"]
要求：用生活化的语言、类比、例子，避免专业术语

**版本 2：专业版本**
面向：[具体人群，如"行业从业者"]
要求：精确的专业术语、技术细节、前沿参考

**对比分析**
请对比两个版本的差异，说明如何在不同场景中选择合适的解释方式。
```

---

### 6. 预演失败（事前验尸）

**核心思想**：在启动项目前，让 AI 假设项目失败，提前发现风险。

**使用场景**：项目规划、产品发布、重要决策、方案评估。

**标准模板**：

```
# 项目/方案
[项目或方案的详细描述]

# 任务
请假设这个项目在 6 个月后**失败了**。

请回答：
1. **失败时间点**：什么时间点开始出现衰退信号？
2. **致命错误**：最致命的决策错误是什么？
3. **被忽视的风险**：哪些风险被我们忽略了？
4. **预防措施**：现在应该采取什么措施来避免这些失败？

请尽可能具体，给出时间线和具体场景。
```

## 三、特定场景技巧

### 7. AI 编程：迭代优化与 TDD

**核心思想**：不要一次写完，分步骤逐步增加功能。

**方法一：迭代优化**

```
第一轮："写一个简单的快速排序函数，用 Python 实现。"
第二轮："很好。给这个函数加上详细注释。"
第三轮："加一个参数，可以选择升序或降序。"
第四轮："加上输入验证和错误处理。"
```

**方法二：测试驱动开发（TDD）**

```
# 任务
使用 TDD 方法开发一个用户登录功能。

请按以下顺序：
1. **先写测试用例**：
   - 正确的用户名和密码应登录成功
   - 错误的密码应返回错误
   - 不存在的用户应返回错误
   - 空输入应返回错误
2. **再写实现代码**：满足这些测试的函数
3. **验证测试**：运行测试用例，确保全部通过
```

### 8. 内容创作：展示而非告知（Show, Don't Tell）

**核心思想**：不要让 AI 直接说"他很悲伤"，而是通过场景描写来展示悲伤。

**正误对比**：

| ❌ 告知 | ✅ 展示 |
|---------|---------|
| "他很悲伤。" | "他盯着冰冷的咖啡，雨滴滑过窗户，远处的钟声敲了十二下。" |
| "房间很乱。" | "衣服堆在椅子上，书本散落在地板，桌上放着半个吃剩的苹果。" |
| "她很紧张。" | "她不停地转着手中的笔，呼吸急促，眼神不敢与对方接触。" |

**提示词模板**：

```
# 写作原则
使用"展示而非告知"的技巧。

# 要求
- ❌ 不要直接用形容词描述情绪/状态（如"他很生气"）
- ✅ 通过动作、环境、细节来间接展示
- 使用感官描写（视觉、听觉、触觉、嗅觉）

# 示例参考
[提供 1-2 个展示而非告知的例子]
```

### 9. 分层结构化（文生图专用）

**核心思想**：放弃自然语言堆砌，采用分层、模块化的画面描述，让生图 AI 精准控制每个要素。

**六层结构**（详见 `image-prompt-template.md`）：

| 层级 | 要素 | 核心问题 |
|------|------|----------|
| 1 | 主体 | 谁/什么？外观特征？ |
| 2 | 动作/状态 | 在做什么？动态还是静态？ |
| 3 | 环境 | 在哪里？时间？天气？ |
| 4 | 构图 | 景别、角度、焦点？ |
| 5 | 光线与氛围 | 光源、色温、情绪基调？ |
| 6 | 风格与画质 | 艺术风格、技术质量？ |

**为什么有效**：AI 生图模型对分层结构比自然语言堆砌更敏感，分层写法让每个要素的权重清晰可控，避免"主体混杂"或"风格冲突"。

---

### 10. 对话式精炼（ChatGPT 生图专用）

**核心思想**：ChatGPT 的图像生成支持对话式迭代——不追求一次完美的 prompt，而是先用自然语言描述画面，再通过多轮对话逐步调整。

**示例流程**：

```
第 1 轮："生成一张产品海报，白色背景，一个运动水壶在中央，阳光从侧面打过来。"

第 2 轮："很好。把水壶颜色换成哑光黑，背景加一点暖色调。"

第 3 轮："在水壶旁边加一行字 'ENDURANCE'，用细体无衬线字体。"
```

**优势**：不需要一次想清楚所有细节，可以在对话中逐步发现和改进。

### 11. 场景特化公式（Nano Banana Pro 专用）

> 模型行为说明截至 2026-07 校验（模型迭代后以官方最新为准）。

**核心思想**：Nano Banana Pro 对结构化描述更敏感。用官方公式组织：**主体 + 动作 + 位置/场景 + 构图 + 风格**。不堆砌空洞质量词（如 `4k, masterpiece`），用具体描述替代。

**公式示例**：

```
[主体] 一位穿黑色风衣的赛博朋克武士，30 岁，面容坚毅，手持发光武士刀。
[动作] 在暴雨中缓步行走，低头凝视手中的刀刃。
[位置/场景] 东京新宿街头，夜晚，霓虹灯闪烁，地面积水反射彩色光芒。
[构图] 中景，低角度仰拍，主体居中，浅景深突出人物。
[风格] 赛博朋克风格，超写实，胶片质感，轻微颗粒感。
```

**文字渲染**：`标题 "NEON RAIN" 用粗体白色无衬线字体，置于画面左下角。`

## 五、最佳实践总结

1. **正向优先** — 用"要什么"定义方向，用"不要什么"划定边界
2. **上下文充足** — 假设 AI 对你的情况一无所知，补充所有关键信息
3. **逐步深入** — 从简单开始，逐步增加复杂度，不要一次追求完美
4. **展示过程** — 让 AI 展示思考过程（CoT），提升可靠性
5. **双向学习** — 用逆向工程理解优秀作品的底层逻辑
6. **事前验尸** — 提前假设失败，主动规避风险
7. **平台适配** — 不同平台需要不同的提示词策略，不要一套写法到处用
8. **迭代优化** — 把提示词当作可迭代的产品，持续改进
