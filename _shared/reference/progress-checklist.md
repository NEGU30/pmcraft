## 流程清单（进度与待办）

> **用途**：为 PM 提供随时可查看的**整体流程账本**——宏观各环节到哪一步、微观"等人处理"待办有哪些、推荐下一步做什么。内容落盘 `{版本目录}/_进度清单.md`，换会话不丢。PM 说「进度 / 清单 / 待办 / 下一步 / 还有什么待处理 / 现在到哪一步」即可触发（路由表命中）；技能出口与会话恢复也按本节刷新。

### 文件约定

- 位置与命名：`{版本目录}/_进度清单.md`（版本目录根，下划线前缀，与 `_README/`、`_index.md` 同级约定：非 PM 产出、由路由大脑维护）。
- 隔离规则：不进 E 编号、不进 `_index.md`、不进 `_README/` 文档三表；`save-doc.js` 仅在 `_README/README.md` 顶部机械维护一行「整体进度」入口。**禁止用 save-doc 保存或手动改名**（save-doc 不识别 doc-type 也不会触碰）。
- 首建与刷新：首个触发点按下方骨架初始化（表头记 {功能名}/{版本号}/最后刷新时间）；此后每次刷新遵循「重写协议」。

### 触发时机（四类）

1. **会话启动/恢复**：推进类路由命中、状态检测得出 NEXT 结论后，先刷新清单再播报（NEXT-{id} 前接 **FLOW-SESS** 两行）；维护会话内记忆"本会话已刷新过清单"，避免每轮重复全量刷新。
2. **补记点技能出口**：write-brief / review-prd / generate-prd / revise-prd / check-consistency 出口执行登记或关闭 → 刷新 → 按 **FLOW-REG** / **FLOW-CLOSE** 播报单行。
3. **PM 显式查询**：路由表「进度/清单/待办/下一步」行命中 → 全量重扫重写 → **FLOW-QUERY** 播报（口播为摘要，文件是权威全文）。
4. **状态迁移事件**（save-doc 保存 / save-version 存档 / run-tests 完成等）：不逐事件刷新（噪音大），由 PM 下一条消息经路由层自然刷新兜住。

### 清单骨架与状态取值（呈现给 PM 看，措辞人话化）

状态取值：`✅ 已就绪 / 🟢 进行中 / 🟡 缺环（缺失或过期）/ ⬜ 未开始 / 🔵 可选`。文件四段式：

```

> 说「进度」可刷新、说「待办」可听口头播报。本文件自动管理，无需手动保存或改名。
```

### 宏观进度推断（输入源 = 状态检测节）

| # | 域 | 环节 | 判定要点 | 缺环 / 未开始时的推进关键词 |

### 微观待办登记协议

- **登记行格式**（7 列，位置列序固定；登记区与推断区同构；文件内显示列头用骨架模板人话措辞）：`行键 | 事项 | 状态 | 登记场景 | 登记日期 | 完成条件 | 备注`。状态取值：`⬜ 待处理 / 🕓 等待条件触发 / ✅ 已完成`——**表内状态列只放单符号 ⬜/🕓/✅，不写字**（语义见全文图例）。行键 = 内部唯一去重键（仅用于合并与口头关闭定位，不进入正文叙述）：`gate1|用户旅程`、`gate1|简报审查`、`report|E{M}|采纳`、`consist|E{M}_r{N}|反向差异`、决策条目直接 `D{编号}`、人工补测 `run|{时间戳目录}|{TC}`。
- **面向 PM 的措辞约定**（生成器与补记点出口共用）：列头显示「编号/事项/状态/产生原因/登记日期/完成条件/备注」；`产生原因` 写"为什么这条出现在你面前 + 从哪一步来"的人话（如「PRD 审查遗留，等你拍板」「自动测试需人工核对」「写简报时约定暂缓」），**不得**只写内部来源名（决策记录更新/run_state 等）；`事项` 直述要做什么（如「PRD 审查提出 8 条修改建议，尚未应用」）；正文与 §3 **禁止**出现行键、盘证据、技能内部名、脚本文件名等内部词（需指引时写人话 + 文档路径）；技术细节只在影响 PM 决策时出现，且用结果语言（如「如需重测，会先重建测试脚本」，不解释 spec.ts 清空）。
- **表格书写纪律**：三表行格式与列数固定（7 列 / 4 列）；空段只保留一行占位 `| _暂无_ | | | | | | |`（已关闭段为 `| _暂无_ | | | |`），**禁止输出多余空行行或空单元格行**（含段尾空行，各段之间空一行即可）。
- **重写协议**：宏观段 / 推断区 / 下一步段**全量重生成**；登记区逐行按行键合并——旧行关闭条件已满足 → 移入 2.3 已关闭（记关闭日期与方式）；未满足 → 原样保留；新登记行追加。
- **关闭三机制**：
  1. **盘证据自动关闭**（主）：生成器探测到关闭条件满足即移入已关闭——Gate 1（对应审查报告落盘）、人工补测（manual-results.json 覆盖对应 TC）、决策条目（状态索引不再含 ❓/⏳）；
  2. **技能出口显式关闭**（辅）：revise-prd 应用采纳后关闭 `report|E{源}|采纳`；check-consistency 复查轮差异清零关闭 `consist|…|反向差异`；
  3. **PM 口头关闭**：PM 说「清单里 X 已处理」→ 有盘证据直接关；无证据关闭并在备注记 `PM 口头确认 {日期}`（如实记录，不伪造证据）。

### 落盘校验纪律（所有刷新/登记/关闭动作强制）

任何刷新、登记、关闭动作完成后，**必须先用 Read 回读 `_进度清单.md` 核对预期变化已物理落盘**（新登记行存在于登记区、已关闭行已迁移至 2.3、宏观状态/计数已更新），回读核对通过后才按 FLOW-* 播报；回读发现未落盘或内容不符 → **立即重写文件后再核对一遍**，确认无误才汇报。禁止用口播"已登记/已更新"代替真实写盘——清单以文件为唯一事实源，会话声称不算数。
