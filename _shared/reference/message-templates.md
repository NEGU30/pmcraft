## 话术模板库

<!-- 话术库 v0.0.1 -->
集中定义全部衔接推荐话术。技能内嵌文本标注 `（话术库 {ID}）`，**模板库是权威，技能副本 1:1 一致**。状态检测表每行挂 NEXT-{id} 引用；技能出口小节引用对应 ID，杜绝双写漂移。

### NEXT 族（状态检测"下一步"）

模板：
```
NEXT-{id}：当前进度：{状态描述}。下一步：{动作}。直接说「{keyword}」即可。
```

已注册具体 ID：
```
NEXT-BRIEF：见下（双路径）
NEXT-PRD-BACK：当前进度：原型已产出、PRD 缺失。下一步：建议新开会话生成 PRD（读取简报+原型），上下文更干净。直接说「生成 PRD」即可。
NEXT-PIPE：当前进度：{proto 流水线阶段}。下一步：{下一环}。直接说「{keyword}」即可。
NEXT-PROTO：当前进度：原型已保存。下一步：{review-ux / 设为主分支并部署 / 回切生成 PRD（PRD 缺失时）}。直接说「{keyword}」即可。
NEXT-REVIEW：当前进度：有 {N} 页改动尚未评审（自 {lastAt}，累计 {M} 轮，攒批中）。下一步：说「保存版本」会先自动批量评审，或现在就说「审查原型」。直接说「审查原型」即可。
NEXT-TAIL（收尾进行中）：{当前环节}已完成。req 域剩余收尾：{缺失环节，按 流程图→时序图→测试用例 顺序}。直接说「继续收尾」即可。
NEXT-TAIL（收尾完成）：测试用例已完成。req 域全部产出就绪。下一步：① 迭代规划（Gate 3 评审，建议新开会话，说「迭代规划」）② 新会话做原型（说「继续做原型」）③ 开发交接（建议新开会话，说「开发交接」）④ 自动化测试（建议新开会话，说「跑测试」）。版本目录 _README/ 门户（双击 README.html：文档点开即读、原型直达启动器）已由 save-doc 自动维护，评审与开发可查看。直接说对应关键词即可。
NEXT-EXPLORE：{分析报告}已保存。下一步可进入方向验证（说「验证方向」）或需求澄清（说「写需求」）。
NEXT-DEV：开发交接完成。输出已就绪供 OpenSpec 消费。后续：自动化测试（说「跑测试」）。
NEXT-TEST：当前进度：{e2e 阶段}。下一步：{setup-tests / run-tests / generate-report}。直接说「{keyword}」即可。
NEXT-WALKTHROUGH：当前进度：测试报告已生成（{n} 条 TC，通过率 {rate}%）。下一步：体验走查（代入用户视角亲手体验产品，说「体验走查」；条件允许可找一位同事走同一清单，说「找个人体验」）或复盘经验（说「复盘」）。
NEXT-COMPACT（可选项，非推进链）：当前进度：完整 PRD 已产出（E{N}）。可选项：生成简版PRD 给开发快速阅读。直接说「简版PRD」即可。
NEXT-COMPACT-STALE（可选项，非推进链）：当前进度：完整 PRD 已修订至 E{N}，现有简版PRD（E{M}）基于旧版 E{源} 生成、已过期。可选项：重新生成简版PRD 给开发看最新要点。直接说「简版PRD」即可。
NEXT-DERIVED-STALE（可选项，非推进链）：当前进度：完整 PRD 已修订至 E{N}，现有{流程图/时序图/测试用例}（E{M}）基于旧版 E{源} 生成、已过期。可选项：重新生成{对应文档}看最新内容。直接说「{流程图/时序图/测试用例}」即可。
NEXT-WORKING（非推进链，前置动作）：当前进度：working/ 有未存档修改（自 {日期}）。下一步：先保存版本存档（说「保存版本」），再做一致性检查/部署，确保基线一致。直接说「保存版本」即可。
```

（EXIT-TAIL 已删除并入本模板——"下一环"衔接职责由 EXIT-CONVERGE 的收尾完成变体承载，无技能引用故无破坏）

### GATE 族（审查关隘）

```
GATE-{n}（n=1/2）：【{审查名}】{前置产物}已完成。根据审查把关线（Gate {n}），建议执行审查：
- {技能1}（{技能1说明}）
- {技能2}（{技能2说明}）
请选择（可多选，如「1+2」）或回复 **跳过**：

GATE-2-FULL（仅 PRD 首次产出时用）：审查把关线（Gate 2）采用收敛小循环：
① PRD 审查 → 对话决策 → 修订定稿 → ② 一致性检查 → ③ 自动处理差异 → ④ 复查直至差异清零。
循环由 AI 自动执行，您在入口决策、反向差异、收敛出口 3 个点确认。
收敛上限：④ 复查最多 3 轮；3 轮后仍有差异 → 输出剩余差异清单并停止循环，由您决策（继续人工修复 / 接受现状）。
请选择：1）执行完整循环（推荐）2）仅质量审查 3）仅一致性检查 4）跳过
（GATE-2 评审提示句——修订技能 GATE-2 副本与 GATE-2-FULL 副本均追加同文：评审提示：版本目录 `_README/`《评审与开发必读指南》由 save-doc 自动维护（双击 _README/README.html 门户即读），评审前可先打开获取全貌）

GATE-1-PARTIAL（Gate 1 部分执行后的补做提醒，仅部分执行时出现）：Gate 1 审查未完整执行：{缺失审查名}尚未执行。是否现在补做？（补做：{对应审查名}；跳过：进入保存阶段）

**填充规则**：{缺失审查名} 与 NEXT-BRIEF 共用同一条填充规则——只做部分写未做的那个（如「简报审查（review-brief）」）；全部未做时不出现本提醒（用户已显式跳过，由 5.7 保存后提醒兜底）。{对应审查名} 为缺失项全名（review-journey → 用户旅程审查；review-brief → 简报审查）。
```

GUARD-ON：Guard-Chat 守卫已开启。教练域/需求域对话将启用输入检测，落盘文档将清除对话客套语，随时可说「关闭Guard-Chat」关闭。

### NEXT-BRIEF（简报完成双路径，默认原型先行）

```
NEXT-BRIEF：简报已完成（{简报路径}）。下一步有两条路径：
{若待验证假设非"无。"，插一行：}（洞察摘要含 {N} 条关键待验证假设。建议先执行方向验证（说「验证方向」），假设确认后再写 PRD/原型。）
① 原型先行（推荐）：先做原型看效果，再回切生成 PRD。适合：演示驱动、视觉敏感、优化现有原型。**建议新开会话做原型**（需求→交互人设切换，上下文更干净）。（说「做原型」）
② 文档先行：先生成 PRD 锚定需求，再补原型。适合：需求边界需文档先行确认。建议新开会话生成 PRD（简报已落盘，衔接点确定）。（说「生成 PRD」）
{若 Gate 1 未完整执行，插一行：}（Gate 1 审查未完整执行：{缺失审查名}尚未执行。建议先做：说「审查简报」）
请选择路径：（不想新开会话也可以继续，直接说关键词即可）
```

**填充规则**（{缺失审查名}）：若 Gate 1 审查完整执行（用户旅程 + 简报审查都做过）→ 该行不出现；若全部未做 → 写「用户旅程 + 简报审查」；若只做了部分 → 写未做的那个（如「简报审查（review-brief）」）。**这是显式待办提示而非弱括注**——Gate 1 未完整时必须在双路径前列出缺失审查项。**{待验证假设}条件行**：简报「待验证假设」章节为"无。" → 该行不出现；非"无。" → 写「洞察摘要含 {N} 条关键待验证假设。建议先执行方向验证（说「验证方向」），假设确认后再写 PRD/原型。」，置于双路径之前（验证优先级高于路径选择）。

**场景判定**（默认值填充）：
- 全新功能（无存量 PRD/原型）→ 默认 ① 原型先行（推荐）
- 存量新增（有存量 PRD）→ 默认 ① 原型先行（回切时 append-prd 生成增量 PRD）
- 优化模式（基于现有原型改）→ 默认 ① 原型先行（天然匹配）
- 存量有 PRD 无原型 → 默认 ② 文档先行（先 append-prd 锚定变更集，再补原型）
- PM 显式偏好 → 尊重 PM 选择

**连带逻辑**：原型先行成为默认路径后，断点 #4「原型完成→PRD 回切」为**默认必切**（回切是标准动作）；"原型直通开发"废弃（见「新会话建议」节）。

FLOW-CLOSE：📋 待办已关闭：{待办简述}。方式：{盘证据 / 技能出口应用完成 / PM 口头确认 {日期}}。清单已更新
FLOW-QUERY：📋 {功能名} {版本} 当前进度：{宏观简表 5-8 行，缺环/未开始用 🟡 标注}。待办 {n} 项：{未关闭待办逐行简述}。推荐下一步：{引用 NEXT-{id}/EXIT 族关键词句，不另造文案}。清单全文：{版本目录}/_进度清单.md（门户入口 {版本目录}/_README/README.html）
