# 新会话建议（pmcraft 参考）

> 从 CLAUDE.md 拆出，供路由按需读取。插件根解析规则同 CLAUDE.md 路由表。

## 新会话建议

**判定标准：看"谁在主导"，不看"出现了谁"。** 主对话流换主导角色 → 切会话；子代理 spawn（借人设干独立活，主对话流角色不变）→ 不切。

### 断点触发分级（6 断点 → 6+1）

| 级别 | 判定 | 断点 | 行为 |
|------|------|------|------|
| **必断**（域边界/人设切换） | 人设文件切换、产出域切换 | #3 req→proto、#4 proto→req、#5 →dev、#6 →test | 每次产出完成都提示，不依赖对话长短 |
| **条件断**（上下文累积） | 对话轮数/产出量阈值 | #1 探索+验证→澄清（探索/验证累计 ≥3 轮）、#2 澄清→撰写（简报已保存） | 达到阈值才提示，短对话不打断 |
| **不提示**（域内） | 同域连续产出 | 探索↔验证内部、proto 七步内部、收尾三件套内部、test 链内部、Gate 审查（spawn 子代理） | 静默推进 |

**断点表：**

| # | 断点 | 触发级别 | 理由 | 话术ID |
|---|------|---------|------|--------|
| 1 | 探索+验证完成 → 澄清（Stage2→3） | 条件断 ≥3轮 | write-brief 需要干净的对话空间 | NEWSESS-1 |
| 2 | 澄清完成 → 撰写（Stage3→4） | 条件断：简报已保存 | 简报已落盘，衔接点确定；**同时输出双路径推荐** | NEXT-BRIEF（内置新开会话提示，即 NEWSESS-2 语义） |
| 3 | 撰写完成 → 原型（req→proto） | 必断 | 人设 需求分析师→交互设计师 | NEWSESS-3 |
| 4 | 原型完成 → PRD 回切（proto→req） | **必断（默认必切）** | 原型先行成为默认路径，回切补 PRD 是标准动作；人设 交互→需求分析师 | NEWSESS-4 |
| 5 | 原型完成 → 开发交接（proto→dev） | 必断 | 人设切换；**修订：无 PRD 时不直通**（见下） | NEWSESS-5 |
| 6 | 需求产出完成 → 测试（req→test） | 必断 | 人设 需求→测试工程师 | NEWSESS-6 |
| 7（新） | 原型保存后（成为交付基线：`--main` 或尚无 main）且 PRD 已存在 → 一致性同步 | 条件断：save-version 出口 | 原型新版本使 PRD 失真，check-consistency 是 Gate2 收敛后半环 | NEXT-PROTO（不新开会话） |

**不提示的情况**：探索↔验证内部、proto 七步内部、收尾三件套内部、test 链内部、thinking-coach / concept-coach / prompt 独立调用、Gate 审查（spawn 子代理）。

**原型直通开发已废弃**：原型完成且 PRD 缺失时，不再"直通开发"。prepare-dev 硬依赖 PRD（无 PRD 终止），故默认**回切生成 PRD**（断点 #4）；PM 明确要求直通时，提示"与开发确认接受无 PRD 的简化交接"后放行。
