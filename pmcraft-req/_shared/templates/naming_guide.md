# 命名规范参考

## 产品层命名

**公式：`[修饰词?] + [核心能力] + [产品形态]`**

### 修饰词（可选）

| 类型 | 用词 | 何时用 | 正例 |
|------|------|--------|------|
| 技术定语 | 智能、实时、自动化、低代码 | 确实使用了相应技术能力 | `实时风控引擎` |
| 场景定语 | 移动端、轻量、企业级 | 限定使用范围 | `企业级权限中心` |
| 差异化定语 | 统一、集中式 | 和同类产品做区分 | `统一消息网关` |

原则：去掉修饰词后别人不会误解产品，就去掉。

### 核心能力

`[领域]` + `[解决问题]`，2-5 个字。

| 领域 | 正例 | 反例 |
|------|------|------|
| 订单、客户、商品 | `订单管理`、`客户中心` | `数据`（只说了领域没解决问题） |
| 权限、审批、消息 | `权限系统`、`消息中心` | `综合管理`（什么都没说清楚） |
| 分润、结算、对账 | `分润计算引擎` | `平台`（没有核心能力） |

### 产品形态

| 用词 | 何时用 | 正例 |
|------|--------|------|
| 平台 | 有多个业务方参与、有生态属性 | `供应链协同平台` |
| 系统 | 功能闭环、相对独立完整 | `订单管理系统` |
| 后台 | 运营/管理端，面向内部操作 | `商家管理后台` |
| 引擎 | 自动化处理、规则驱动 | `分润计算引擎` |
| 工具 | 单点功能、轻量级辅助 | `数据迁移工具` |
| 中心 | 集中管理某类资源或数据 | `客户中心`、`权限中心` |

原则：选最小的能说清楚形态的词。

## 功能层命名

**公式：`[场景限定?] + [动词] + [业务对象]`**

### 场景限定（可选）

| 类型 | 用词 | 正例 |
|------|------|------|
| 批量类 | 批量、全量、增量 | `批量导入客户` |
| 自动化类 | 自动、定时、周期 | `自动生成对账单` |
| 条件类 | 按条件、自定义 | `按条件筛选客户` |
| 方式类 | 手动、一键 | `一键生成报表` |

原则：只有需要区分时才加限定。一个产品只有一个导入功能时，就叫"导入客户订单"。

### 动词库

| 操作类型 | 推荐动词 | 禁止用词 |
|----------|---------|---------|
| 新增 | 创建、录入、注册、登记 | 新增、添加 |
| 读取 | 查询、检索、浏览 | 查看、列表 |
| 更新 | 编辑、修改、更新 | 处理、维护 |
| 删除 | 删除、作废、注销 | 移除、清理 |
| 批量 | 导入、导出、同步、迁移 | 上传（不准确时） |
| 审批 | 审批、审核、复核 | 处理、操作 |
| 生成 | 生成、输出、计算 | 创建（不够准确时） |
| 配置 | 配置、设置、定义 | 管理、维护 |
| 发送 | 发送、推送、通知 | — |
| 关联 | 绑定、关联、映射 | — |

### 业务对象

功能的作用实体，使用统一的领域术语：

- 同一实体在全公司用同一名称（"客户"=customer，不要今天客户明天顾客后天甲方）
- 子对象从父对象继承命名（`生成结算单` → `审核结算单` → `导出结算单`）
- 避免把"数据""信息"当业务对象（`导入客户` 好于 `导入客户信息`）

---

## 跨层一致性规则

1. **同一实体，同一名称** — 产品层叫"客户管理系统"，功能层就不能出现"顾客导入"
2. **避免同层重名** — 两个产品不能都叫"数据平台"，两个功能不能都叫"订单查询"
