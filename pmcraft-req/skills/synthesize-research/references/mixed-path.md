# 混合分析路径方法论

## 适用场景

PM 选择了 ≥2 种数据类型。

## 核心原则

**定性来源共享一套标引-聚类流水线，定量来源独立分析，最后交叉验证。** 不做"分别出报告再合并"——那样会导致同一现象在不同来源的分析报告中以不同方式呈现，无法建立跨来源证据链。

**两阶段约束**：阶段一（第一步至第四步）为机械核查，产出结构化事实表，不做推断。阶段二（第五步至第八步）为模式识别，基于阶段一已验证的事实做推理，禁止重新计数。

## 分析流程

### 第〇步：合约解析（条件执行）

**触发条件**：PM 提供了调研计划时执行。若未提供，跳过本步，标注"未提供调研计划"。

从调研计划中抽取并输出为执行清单（抽取表同问卷分析路径 Phase 0）。执行清单在第八步逐项对账。

---

## 阶段一：机械核查

### 第一步：分流

将 PM 提供的数据按形态分为两流：

| 归入定性流 | 归入定量流 |
|:---|:---|
| 访谈记录（全文叙事） | 问卷封闭题（选项/量表/排序数据） |
| 可用性测试记录 | 行为分析数据（漏斗/留存/使用率） |
| 工单正文（有场景描述） | A/B 测试结果 |
| 问卷开放题回答 | — |
| 内部反馈（销售/客服转述） | — |

### 第二步：定性流 — 统一标引

所有定性来源的工件放在同一个池子里标引。

**标签格式：**
- `[访谈#N] 导出超时-大文件`：导出大文件时等待超过 30 秒
- `[工单#N] 导出超时`：用户工单反映导出超时
- `[开放题#N] 导出太慢`：问卷开放题中提及导出性能问题

**关键**：标引时不区分来源类型——同一条关于"导出性能"的标签，可能来自访谈、工单、问卷开放题三种来源。标签的工件类型标注只是为了在后续聚类时验证证据的多样性。

⚡ **批判性停顿：统一标引 → 统一聚类**

在进入聚类前，对标引结果执行以下反思。**发现问题后回退修正，不修正不允许进入下一阶段。**

| 维度 | 问题 |
|:---|:---|
| 确认偏误 | ① 多来源标引时，我是否对某一来源类型（如访谈的叙事细节）给了更多权重，而对另一来源类型（如工单的简洁描述）打了不同的标签？② 是否因为某个模式在访谈中"故事好讲"就忽略了它在其他来源中的缺乏？ |
| 替代解释 | ① 不同来源的同一标签是否真的指向同一现象——还是它们只是用了相似的词但指向不同问题？② 不同来源覆盖的用户群体不同（如访谈=活跃用户，工单=投诉用户），标签的跨来源一致性是真实模式还是巧合？ |
| 宣称强度 | ① 跨来源一致的标签在标注时是否明确了来源多样性（如"访谈+工单"）？② 仅来自一种来源的标签是否标注了 `[仅{类型}来源]`？ |

### 第三步：定性流 — 统一聚类

在全部标签上做聚类。同一个簇包含多种来源的工件是理想情况——这意味着同一个现象被不同的数据收集方法独立发现。

**簇内一致性检验**：一个簇内的所有标签，应当能用同一句"这是因为 X"来解释其产品含义。如果一个标签的解释是"因为信息粒度不匹配"而另一个是"因为做小需求不划算"，即使它们发生在同一个产品环节，也应视为两个不同的簇。

**示例：**

```
簇 A: "导出性能瓶颈"
├─ [访谈#3] 导出 200 行等了 45 秒
├─ [访谈#5] >100 行就不用导出改用 API
├─ [访谈#7] 导出成功率约 60%
├─ [工单#1247] 导出超时
├─ [工单#1302] 导出超时
├─ [工单#1456] 导出一直转圈最后失败了
├─ [开放题#18] 导出太慢，希望能后台导出
├─ [开放题#35] 数据一多导出就不能用
└─ 支撑工件：3 位受访者 + 12 条工单 + 7 条开放题回答
   来源多样性：访谈 + 工单 + 问卷 — 强交叉验证
```

**门禁规则**（同访谈路径 Phase 3，但多一个维度）：
- 簇 < 3 个独立工件 → tentative
- 簇仅来自一种工件类型 → 标注 `[仅{类型}来源，需其他来源验证]`
- 簇有矛盾证据 → `[需进一步验证]`

### 第四步：定量流 — 独立分析

按问卷分析路径或行为数据分析路径执行定量分析，产出定量发现列表。定量流也遵循问卷路径的阶段一纪律——先产出频次分布表和交叉表，不做推断。

⚡ **批判性停顿：定性聚类 + 定量 → 交叉验证**

在进入交叉验证前，对两流产出执行以下反思。**发现问题后回退修正，不修正不允许进入下一阶段。**

| 维度 | 问题 |
|:---|:---|
| 确认偏误 | ① 定性流聚类时，我是否无意中用了定量流的发现来"引导"定性标签——导致两流最终看似一致但实际上只是重复了我的先入之见？② 定量流中发现的显著差异是否掩盖了定性流中不一致的细微模式？ |
| 替代解释 | ① 定性或定量任何一方发现了但另一方没发现的模式——是数据缺失还是实际矛盾？② 如果矛盾，我是否准备好标注 `[来源矛盾]` 而非强行统一？ |
| 宣称强度 | ① 定性流的簇是 ≥3 个工件还是 tentative？tentative 的簇不应进入交叉验证。② 定量流的小样本（N<30）差异是"指示性"还是"统计显著"——标注是否正确？ |

---

## 阶段二：模式识别

阶段二基于阶段一已验证的事实做推理。**禁止重新计数。**

### 第五步：交叉验证与整合

将定性流的命名模式与定量流的发现列表进行匹配。

**匹配结果及处理：**

| 匹配结果 | 标注 | 可信度 |
|:---|:---|:---:|
| 定性模式 ↔ 定量发现 一致 | `[交叉验证]` | 高 |
| 定性有但定量无对应 | `[需定量验证]` | 中 |
| 定量有但定性无解释 | `[需定性验证]` | 纳入待验证假设 |
| 定性说 A、定量说 B | `[来源矛盾]` | 标注矛盾，分析可能原因 |

**矛盾处理：**

当定性来源和定量来源对同一问题的结论矛盾时：
1. 同时展示双方数据，不强求统一
2. 分析可能原因：
   - 人群不同：访谈样本 ≠ 问卷样本（如访谈全是活跃用户，问卷覆盖了沉默用户）
   - 说的 ≠ 做的：用户在访谈中描述的是理想行为，问卷/行为数据记录的是实际行为
   - 问题表述不同：访谈问的是开放式体验，问卷问的是具体功能满意度
3. 标注 `[来源矛盾，需进一步验证]`

### 第六步：综合洞察排序

```
交叉验证的洞察（定性+定量一致） > 仅定性支持（但来源多样） > 仅单一定性来源 > 仅定量信号 > 待验证假设
```

⚡ **批判性停顿：综合洞察 → 三角验证声明**

在产出最终洞察前，对洞察排序执行以下反思。**发现问题后回退修正，不修正不允许进入下一步。**

| 维度 | 问题 |
|:---|:---|
| 确认偏误 | ① 综合洞察排序中，"交叉验证的洞察"是否真的来自独立的两流分析——还是因为我在第一步分流时就用了同一套预期框架？② 是否有洞察被排在靠后位置不是因为证据弱，而是因为它"不那么有趣"？ |
| 替代解释 | ① "定性+定量一致"的洞察——是否有第三种解释两者都支持但两者都错的可能？② "定性有定量无"的洞察——是定量题项没覆盖到，还是定性样本的偏差？ |
| 宣称强度 | ① 每条洞察的信任度标注（高/中/低）是否正确反映了来源多样性和一致性？② 三角验证声明中"方法论三角"是否真的涵盖了至少两种独立方法（而非同一方法的不同变种）？③ 处理陈述的冲突时，是否标注了“来源矛盾”并附原因分析？ |

### 第七步：三角验证声明

汇报本次分析的交叉验证情况：

| 三角维度 | 覆盖情况 |
|:---|:---|
| 方法论三角（不同方法同结论） | 洞察 #1, #2 在访谈+问卷+工单中一致 |
| 来源三角（不同人群同结论） | 洞察 #1 覆盖活跃用户+付费用户；洞察 #3 仅来自活跃用户 |
| 时间三角（不同时间同结论） | 未检测（数据均为单次收集） |

### 第八步：合约对账

**触发条件**：第〇步已执行（即 PM 提供了调研计划）。

逐项检查第〇步抽取的执行清单。对账规则和状态标注同问卷分析路径 Phase 7（合约对账）。定性流和定量流各自对账——定性流检查假设验证和主题覆盖，定量流检查分层对比和偏差规则执行。

## 条件产出物门禁

条件产出物的通过条件和降级规则统一维护在 `quality-gates.md`（与本文档同目录，门禁 B 判定标准）。混合路径的独特规则：多来源互补 → 取各来源路径中最宽松的通过条件。
