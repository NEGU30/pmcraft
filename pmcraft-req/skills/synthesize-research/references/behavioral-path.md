# 行为数据分析路径方法论

## 适用数据类型

- 产品使用数据（DAU/MAU、功能使用率、页面访问）
- A/B 测试结果
- 用户行为漏斗数据
- 留存/流失数据

## 行为数据的特点

行为数据回答最准确的"做了什么"，但完全无法回答"为什么"和"怎么想"。

**分析姿态**：行为数据用来发现"什么地方值得追问"，而不是用来直接产出洞察和建议。所有基于行为数据的"产品含义"和"决策建议"都是 AI 推断，必须全部蓝色标注，并附验证建议。

## 四阶段分析序列

### Phase 1: 数据概览

| 维度 | 内容 |
|:---|:---|
| 数据来源 | 分析工具/数据库名称 |
| 时间段 | {日期范围} |
| 指标定义 | DAU = 每日至少打开一次应用 / 等等 |
| 数据质量声明 | 有无数据缺失、采样偏差、埋点遗漏 |

### Phase 2: 行为模式发现

按数据提供的内容选择分析维度（不做没有数据的分析）：

| 数据中有 | 分析维度 |
|:---|:---|
| 页面访问 / 点击流 | 路径分析 —— 用户常走哪些路径？最常在哪些步骤退出？ |
| 功能使用 | 功能使用率排行 —— 哪些功能高频使用、哪些几乎不用？ |
| 漏斗数据 | 漏斗分析 —— 哪一步流失最高？不同群体的流失点是否不同？ |
| 留存数据 | 留存分析 —— 哪个环节后用户不再回来？D1/D7/D30 留存率？ |
| 分群数据 | 分群对比 —— 高频 vs 低频用户的行为差异？付费 vs 非付费的差异？ |

每条发现标注为客观的行为事实（黑色），不做解读。

⚡ **批判性停顿：行为模式 → 假设生成**

在进入假设生成前，对行为模式执行以下反思。**发现问题后回退修正，不修正不允许进入下一阶段。**

| 维度 | 问题 |
|:---|:---|
| 确认偏误 | ① 我是否注意到了一个"可解释"的下降/上升，而忽略了"什么也没发生"的时段——后者可能同样有信息量？② 是否因为某个漏斗步骤"看起来像"问题点而忽略了其他同样流失率高的步骤？ |
| 替代解释 | ① 行为模式反映的是"用户被迫的选择"而非"用户偏好的选择"？（如某个功能使用率低是因为入口深而非用户不需要）② 群体行为差异（高频vs低频）是群体特质还是"先用了才爱用"的颠倒因果？ |
| 宣称强度 | ① 所有模式发现是否保持了"客观事实"的描述（黑色），不包含任何"因为""所以"的因果语言？② 因果语言应保留到 Phase 3 的假设——那里全部蓝色标注。 |

### Phase 3: 假设生成

基于行为模式，生成待验证的产品假设。

**假设格式：**

> **假设 #N**：用户在 {X 环节} 的流失可能是因为 {Y 原因}
> - 支撑数据：{行为模式发现}
> - 假设类型：`[AI 推断]`
> > 验证方式：{建议的验证方法——补访谈 / design-survey / A/B 实验}

**纪律：**
- 全部蓝色标注：行为数据不告诉你"为什么"，所有因果解释都是假设
- 每条假设至少给出一种验证方式
- 不做优先级判断——行为数据的模式发现 + 假设列表是给 PM 看的，让 PM 决定优先验证哪个

⚡ **批判性停顿：假设 → 验证建议**

在进入验证建议前，对假设列表执行以下反思。**发现问题后回退修正，不修正不允许进入下一阶段。**

| 维度 | 问题 |
|:---|:---|
| 确认偏误 | ① 每条假设是否真的来自行为模式的支撑，还是来自我对产品的预设立场？② 是否因为某个假设"看起来很重要"而给了它比数据支撑更强的措辞？ |
| 替代解释 | ① 每个行为模式→假设的推理中，是否存在同一样数据支撑另一种因果方向可能？如果是，标注"另一种可能：XXX"。② 假设是否混淆了"相关"与"因果"？ |
| 宣称强度 | ① 是否全部假设已蓝色标注 + `[AI 推断]`？② 每条假设是否都已附验证方式？③ 是否有假设声称了"用户因为 X 所以 Y"但行为数据只能看到"Y 发生时 X 也存在"？ |

### Phase 4: 验证建议

将假设按验证途径归类，给出建议的下一步：

| 假设 | 建议验证方式 | 验证成本 | 
|:---|:---|:---:|
| 假设 #1（流失原因） | 定向访谈 3-5 名流失用户 | 中 |
| 假设 #2（功能使用差异） | design-survey 设计定向问卷 | 中 |
| 假设 #3（路径问题） | A/B 测试优化后的路径 | 高 |

⚡ **批判性停顿：验证建议 → 产出**

在进入最终产出前，对验证建议执行以下反思。**发现问题后回退修正，不修正不允许进入下一步。**

| 维度 | 问题 |
|:---|:---|
| 确认偏误 | ① 行为模式发现中是否有任何一个发现被解释为"用户喜欢/不喜欢"——行为数据不知道"喜欢"？② 是否因为数据来自特定时间段（如季度末、节假日）而可能不代表常态？ |
| 替代解释 | ① 是否存在第三变量（如营销活动、产品改版、季节性）可以解释观察到的行为变化而未被提及？② 不同群体间的行为差异是否可能由入口或权限差异导致而非偏好差异？ |
| 宣称强度 | ① 是否在报告开头声明了"行为数据不通知为什么，所有因果解释都是假设"？② 验证建议中的验证成本估算是否标注了是估算？ |

## 条件产出物

行为数据**不产出**以下模块（无叙事信息、无直接痛点描述）：

| 模块 | 原因 |
|:---|:---|
| 用户画像 | 行为数据只看得到行为，看不到目标/场景/情绪/原话 |
| 痛点排序 | 行为数据只显示"哪里有问题"，不显示"用户有多痛" |
| 机会点陈述 | 行为数据无"当前做法/变通方案"信息 |

产出的核心是**行为模式发现 + 待验证假设列表**，作为后续定性研究（访谈/用户测试）的输入。
