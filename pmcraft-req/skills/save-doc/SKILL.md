# 文档保存 (save-doc)

## 概述

**本技能源码目录**：当前 SKILL.md 所在目录（如 `.../pmcraft-req/skills/save-doc/`），脚本路径一律由此锚定解析，不依赖 cwd。

`save-doc` 是一个基础设施技能，所有文件系统操作由 `scripts/save-doc.js`（Node.js）完成，技能负责参数收集、版本号确认和结果展示。

### 核心能力
- **自动初始化完整目录结构**：当保存到新版本目录时，会自动创建包括 `brief/`、`prd/`、`report/`、`testcase/`、`meeting/`、`planning/`、`decision/`、`flowchart/`、`sequence/`、`survey/`、`analysis/`、`development/`、`prototype/` 在内的标准目录树，确保项目从一开始就具备正确的骨架。已有项目无需迁移——下次保存时自动补建 `development/`。
- **智能 E编号管理**：扫描目标目录中已有同类型文档，自动计算下一个 E编号，不会覆盖历史版本。每种文档类型（需求简报、PRD、各类报告、产品迭代规划等）拥有独立的 E编号序列。
- **规范性文件命名**：严格遵循 `功能名_版本号_文档类型_E编号.md` 格式，版本号支持两种格式：`1.0.0`（推荐，无V前缀，与 proto-agent 一致）和 `V1.0.0`（兼容旧格式），文档类型使用中文名称。功能名称优先从顶级文件夹下的 `.feature-name` 文件读取，不存在时降级使用文件夹名。
- **灵活的调用方式**：支持直接传参供其他技能静默调用，也支持交互式引导供用户手动使用。
- **自动维护必读指南**：每次保存文档后自动刷新 `{版本目录}/_README/`（README.md 数据源三表结构 + README.html 门户：文档点开即读、原型直达启动器），路径实时扫描填充，未产出标注「未产出」，脚本机械生成无 LLM 参与。

| 参数 | 类型 | 必选 | 说明 | 示例 |

| `--readme-only` | 开关 | 否 | 仅手动重刷 `_README/`（README.md + README.html 门户），不保存文档；须配合 `--version` | — |
| `--summaries-file` | 文件路径 | 否 | IndexOnly 模式的 Summaries JSON 文件路径 | `C:/项目/账号系统/pmcraft/temp/summaries.json` |

| `--skip-precheck` | 开关 | 否 | 跳过预保存质量检查（不推荐，仅临时用） | — |

> **条件必选说明**：`--summary` / `--author` 的"条件必选"指**当需要脚本在 `_index.md` 中为该文档写入内容摘要与负责人列时必选**（含修订文档的变更说明，便于索引快速识别主题/变更）；不需要索引摘要时可省略，省略后该文档在索引中无摘要/负责人行，后续可经 IndexOnly 模式（`--index-only --summaries-file`）补写。

> **临时文件位置**：`--temp-file` / `--summaries-file` 统一写入 `<项目根>/pmcraft/temp/`（若不存在则先创建）。**禁止写入系统 Temp 或 cwd**——写入项目内临时区确保中途失败时产物可追踪；保存完成后临时文件默认删除（`--keep-temp` 指定时保留）。

> **模式与必选差异**：必选参数随运行模式变化——**正常保存**需 `--base-dir` + `--version` + `--doc-type` + `--temp-file`；**`--index-only`** 仅需 `--base-dir`（`--summaries-file` 可选；`--version`/`--doc-type`/`--temp-file` 均不使用）；**`--readme-only`** 需 `--base-dir` + `--version`。以 `scripts/save-doc.js` 的必选校验为准。

## 指令

### 第一阶段：参数确认

1. **若收到完整参数**（被其他技能静默调用） → 直接执行第四阶段（运行 save-doc.js）。
2. **若参数不全**（用户手动输入 `save-doc` 或缺失必选参数） → 进入第二阶段（交互式引导）逐一收集缺失参数；收集完成后进入第三阶段（版本号确认），再执行第四阶段（运行脚本）。
3. **在收集参数前**，先扫描 `功能顶级文件夹/*/` 获取已有版本号（使用 Glob 工具），用作版本确认的推荐值。

### 第二阶段：交互式引导（参数不全时执行）

按顺序向用户提问，每次一个问题，收集一个参数：

1. **功能顶级文件夹**：
   > 请提供功能顶级文件夹路径（例如 C:/项目/账号系统）：

2. **功能版本号**：
   - 扫描 `功能顶级文件夹/*/` 获取所有子目录名
   - 筛选符合 `1.0.0` 或 `V1.0.0` 格式的版本目录
   - 按语义版本排序找出最大版本号
   - 推荐递增策略：最大修订号 +1（保持与已有版本一致的格式）
   - 如果无已有版本，推荐 `1.0.0`
   - 输出提示：
     > 检测到已有版本：{已有版本列表}。最大版本为 {最大版本}。请确认本次使用的版本号（按 Enter 使用 {推荐版本}，或输入自定义版本号）：
   - 如果用户按 Enter → 使用推荐版本
   - 如果用户输入自定义版本 → 使用用户输入的版本

3. **文档类型**：
   > 请提供文档类型（{可选列表，用 / 分隔}）：

4. **临时文件路径**：
   > 请提供临时文件路径：

5. **内容摘要**（可选，用于 `_index.md`）：
   > 请提供内容摘要（可选）：

6. **负责人**（可选，用于 `_index.md` 负责人列）：
   > 请提供负责人昵称（可选，如 李四<1002>）：

### 第三阶段：版本号确认

> 本阶段在**交互模式**下执行（第二阶段收集参数后进行）。**若版本号已在第二阶段步骤 2 确认，本阶段直接采用已确认值，不再重复询问**；若调用方直接传参（静默调用），版本号已由调用方指定，跳过本阶段直接执行第四阶段。

1. 用 Glob 扫描 `功能顶级文件夹/*/` 获取所有子目录名。
2. 筛选符合 `1.0.0` 或 `V1.0.0` 格式的目录。
3. 按语义版本排序，找出最大版本号（若无则提示"暂无已有版本"）。
4. 检测已有版本目录的格式风格：
   - 若已有版本目录使用 `V` 前缀（如 `V1.0.0`），新版本沿用此格式
   - 若已有版本目录无 `V` 前缀（如 `1.0.0`），新版本沿用此格式
   - 若完全无已有版本（全新项目），推荐使用无 `V` 前缀格式（`1.0.0`）
5. 向用户展示：
   > 检测到当前最大版本为 `{最大版本}`。请确认本次使用的功能版本号：
   > - 按 Enter 使用推荐版本 `{推荐版本}`
   > - 或直接输入你想要的版本号
6. 用户按 Enter → 使用推荐值；用户输入自定义 → 使用输入值。

> ⚠️ **版本号格式与目录命名一致**：`--version` 必须与目标版本目录名格式一致（目录是 `1.0.0` 就传 `1.0.0`，目录是 `V1.0.0` 就传 `V1.0.0`）。版本号参与文件名与 E 编号正则匹配，格式不一致会导致扫描不到已有 E 编号而重新从 E1 计。

### 第四阶段：运行 save-doc.js（核心保存操作）

**Node 原生 UTF-8，无 Bash→PowerShell 编码断裂问题**。中文参数可直接通过 `--key=value` 传递，路径支持正斜杠/反斜杠。**统一使用正斜杠**（`C:/项目/账号系统`）保持一致。

> **参数安全（Bash 注入防护）**：`--summary`/`--author` 来自文档内容提炼或用户输入（文件内容拼接），构造 Bash 命令前必须剔除 `"` `` ` `` `$` `;` `&` `|` `(` `)` 等 shell 元字符（或请用户修改表述），全部参数值用双引号包裹后传入。含非法字符时以剔除后的内容提交并在结果展示中注明，不中断流程。

```bash
node "{本技能源码目录}/scripts/save-doc.js" \
  --base-dir="C:/项目/账号系统" \
  --version="1.0.0" \
  --doc-type="PRD" \
  --temp-file="C:/项目/账号系统/pmcraft/temp/prd_temp.md" \
  --summary="新增账号批量导入功能" \
  --author="李四<1002>"
```

**脚本路径**：`{本技能源码目录}/scripts/save-doc.js`（本技能源码目录 = 当前 SKILL.md 所在目录，不依赖 cwd；其他技能调用时同理以 `{本技能源码目录}` 锚定）
**脚本作用**：创建目录树 → 按文档类型归类 → 扫描 E 编号 → 复制临时文件 → 清理临时文件 → 重建 `_index.md`
**脚本输出**：单行 JSON（`{"status":"ok"|"error","data":{...}}`）

> **环境前置（Node.js，对应 `dependencies`）**：`save-doc.js` 依赖 Node.js（LTS）。若运行前 `node` 命令不可用（报 `command not found` / `'node' 不是内部或外部命令` 等），**停止保存流程**并提示用户"请安装或检查 Node.js（LTS）环境后重试"；**不得**因环境缺失而跳过保存、也不得改用 Write 直接写入版本目录（见"禁止行为"第 3 条）。此降级走向与 `dependencies` 声明一致。

#### IndexOnly 模式（仅更新索引，不保存文件）

当需要为历史文档补充摘要时，LLM 先逐文件读取生成摘要，组装 Summaries JSON，写入临时文件后调用：

```bash
node "{本技能源码目录}/scripts/save-doc.js" \
  --base-dir="C:/项目/账号系统" \
  --index-only \
  --summaries-file="C:/项目/账号系统/pmcraft/temp/summaries.json"
```

`--summaries-file` 内容格式（key 为 `版本|子目录|子分组|E编号`）：
```json
{"1.0.0|brief||E1":{"summary":"初始需求简报","author":"李四<1002>"},"1.0.0|prd||E1":{"summary":"电商平台PRD初稿","author":"李四<1002>"}}
```

### 第五阶段：结果反馈

1. 解析 save-doc.js 返回的 JSON。
2. 按成功/失败模板展示结果（见"输出模板"）。
3. 若 JSON 中包含 `files_needing_ai_summary`（非空），自动补充历史文档摘要：
   - 逐个读取列表中的文件
   - 新文档生成一句话描述主题/范围
   - 修订文档生成一句话描述变更内容
   - 组装 `Summaries` 字典（key 格式：`版本|子目录|子分组|E编号`）
   - 通过 IndexOnly 模式（`--index-only --summaries-file`）回写索引
   - 完成后不重复输出保存结果，仅标注 `📊 _index.md 摘要已补充`
4. **标注自动刷新衔接**（完整 PRD 保存后）：如果 `data.doc_type` **精确等于** `"PRD"`（必须精确匹配，不能用"含"——"简版PRD"含"PRD"子串，保存简版自身会误触标注刷新；annotate-prototype 明确排除简版PRD 作溯源依据）且 `{版本目录}/prototype/working/annotations/` 目录存在 → 自动调用 `Skill(pmcraft-proto:annotate-prototype)`（refresh）——补 PRD 用例溯源（R 规则 → 用例N/章节语义匹配），锚点同步。**refresh 按增量规则执行**：PRD 保存通常页面未变（基线比对 0 页变化）→ 仅做 PRD 溯源更新（基线 `prototype/.last-check.json` 的 `prdE` 字段对比决定是否重读 PRD，E 相同则跳过读取），**不重读页面 DOM**，锚点从旧 `annotations/{page}.js` 复用。完成后在保存反馈中追加一句："已同步刷新原型标注（PRD 溯源已更新）"。此衔接覆盖 generate-prd / append-prd / revise-prd / revise-from-meeting 四条完整 PRD 路径（均经 save-doc 落盘）。
5. **简版PRD 过期提示**（完整 PRD 修订后）：如果 `data.doc_type` **精确等于** `"PRD"`（**必须精确匹配，不能用"含"**——"简版PRD"含"PRD"子串，保存简版自身会误报"简版过期"）：
   - Glob `{版本目录}/prd/*_简版PRD_E*.md`（版本目录定位同步骤 4）→ 无匹配 → 静默跳过，不追加任何内容（首次 E1 生成、从未生成过简版均天然静默）
   - 有匹配 → 取文件名中 E 编号**最大**者（简版 E 序列独立递增，最大即最新；多份简版时旧简版保留不动）
   - Read 该文件前 15 行，提取源完整版 E 编号，**两级回退**：① 文件头引用行 `完整版：`{功能名}_{版本}_PRD_E{源编号}.md`` ② 第 1 章修订简介 `基于完整PRD E{源编号}`；两者均取不到 → 静默跳过（不误报）
   - 若源 E{源编号} < 本次保存的 `data.edition`（E{N}）→ 在保存反馈中追加一句："⚠️ 简版PRD 已过期：现有简版（E{M}）基于完整 PRD E{源}，本次修订已至 E{N}。可选项：重新生成简版（说「简版PRD」）。"（NEXT-COMPACT-STALE 对话变体，话术库）
   - 此衔接覆盖 generate-prd / append-prd / revise-prd / revise-from-meeting 四条完整 PRD 路径（均经本技能落盘）；compact-prd 保存的"简版PRD"自身因精确匹配被排除
6. **衍生文档过期提示**（完整 PRD 修订后）：如果 `data.doc_type` **精确等于** `"PRD"`（同步骤 5 精确匹配规则——"简版PRD"含"PRD"子串，保存简版自身会误报，必须排除）：
   - 按三类衍生文档检查（版本目录定位同步骤 4；无匹配的组静默跳过）——共五组 Glob：
     - `flowchart/*_流程图_E*.md`、`sequence/*_时序图_E*.md`（各取文件名 E 编号最大者）
     - `testcase/*_测试用例_E*.md`（标准系列）、`testcase/*_测试用例_中_E*.md`（中质量系列）、`testcase/*_测试用例_高_E*.md`（高质量系列）——三套独立 E 序列文件名结构天然互斥（`*_测试用例_E*.md` 不会命中 `_中_E`/`_高_E` 文件），各序列取 E 编号最大者
     - **拆分文件兜底组**（防非标准命名文件逃逸检测）：另 Glob `testcase/*测试用例*E*.md`（宽松全量），减去上述三套标准序列已命中的文件，余集即拆分/非标准命名文件（如模块名插入式 `*_测试用例_{模块名}_高_E*.md`）；余集按"去掉尾部 `_E{N}` 的文件名"分组，各组取 E 编号最大者为代表（与标准序列语义对齐），代表同样参与下方 Read 与过期判定
   - Read 每组最新文件前 15 行，提取源 PRD E 编号，**两级回退**：① 文件头引用行 `源 PRD：{功能名}_{版本}_PRD_E{源编号}.md`（流程图/时序图/测试用例同款，见 generate-flowchart / generate-sequence / generate-testcase 模板）② 元信息表/文档内 PRD 文件名引用（测试用例的「PRD 文件名」行；流程图/时序图无第二级）——两者均取不到 → 该组静默跳过（不误报，同步骤 5 逻辑）
   - 若源 E{源编号} < 本次保存的 `data.edition`（E{N}）→ 在保存反馈中追加一句：`⚠️ {文档类型} 已过期：现有{文档类型}（E{M}）基于完整 PRD E{源}，本次修订已至 E{N}。可选项：重新生成（说「{流程图/时序图/测试用例}」）。`（NEXT-DERIVED-STALE 对话变体，话术库）。**{文档类型} 指文档类型名**（流程图/时序图/测试用例/测试用例_中/测试用例_高，不含文件名；**拆分文件兜底组的类型名为"测试用例拆分文件"，其后括号内列出文件名——≤3 份逐个列出，>3 份列首份+"等 N 份"**）；**同源 E 的组合并为一行**——多组基于同一源 E{源} 时并列列出，只报一次"基于完整 PRD E{源}"。合并示例（流程图中/高系列同基于 E1，本次修订至 E2）：
     - `⚠️ 流程图、测试用例_中、测试用例_高 已过期：现有流程图（E1）、测试用例_中（E1）、测试用例_高（E1）基于完整 PRD E1，本次修订已至 E2。可选项：重新生成（说「流程图」或「测试用例」）。`

## 禁止行为

1. **禁止在参数不全时静默失败** — 必选参数缺失时必须触发交互式引导或明确报错，不得以空值或默认值替代用户未提供的关键参数
2. **禁止覆盖已有文件** — E 编号自动递增，相同文档类型仅在确认后覆盖同名文件，不得在未询问用户的情况下覆盖历史版本
3. **禁止绕过脚本直接 Write** — 所有文件写入必须通过 `save-doc.js` 脚本完成，调用方不得直接使用 Write 工具写入版本目录下的文件
4. **禁止使用空临时文件保存** — 保存前确认临时文件非空；0 字节临时文件脚本会报错，调用方应检查临时文件
5. **禁止跳过预保存质量检查** — 四项检查（Mermaid 闭合、span 标签开闭平衡、占位符替换、版本号格式）由脚本保存前自动执行，不合格时脚本拒绝保存并返回精确行号
6. **禁止手动编辑 `{版本目录}/_README/README.md` 与 `_README/README.html`** — 《评审与开发必读指南》由脚本机械生成、每次保存后覆盖更新（含路径），手动修改不会保留；如需修正路径，应修正实际文档/目录后由脚本重新生成

## 约束

1. **版本号格式必须与目录一致** — `--version` 与版本目录名格式必须一致（`1.0.0` 或 `V1.0.0`），否则 E 编号扫描不到历史文件。
2. **接口契约不可变更** — 不得修改 `scripts/save-doc.js` 的实现逻辑或 JSON 输出契约（`{"status":"ok"|"error","data":{...}}`）。本技能被多个技能依赖，任何接口变更必须先与全部调用方同步。
3. **路径统一使用正斜杠** — 所有传入脚本的路径统一使用正斜杠格式（`C:/项目/账号系统`），禁止混用反斜杠。
4. **临时文件必须写入项目临时区** — `--temp-file` / `--summaries-file` 必须位于 `<项目根>/pmcraft/temp/`，禁止写入系统 Temp 或 cwd。

### 错误示例

**错误 1**: 版本号使用小写 `v` 开头
```
save-doc.js --version="v1.0.0"
```
- 问题：版本号须为 `1.0.0`（推荐）或 `V1.0.0`（兼容）格式。小写 `v` 开头不被脚本识别。
- 正确做法：使用 `1.0.0` 或 `V1.0.0` 格式。

**错误 2**: 临时文件路径指向不存在的文件
```
save-doc.js --temp-file="C:/项目/账号系统/pmcraft/temp/nonexistent.md"
```
- 问题：脚本无法读取不存在的文件，保存操作失败。
- 正确做法：确保临时文件已写入后再调用 `save-doc`。

**错误 3**: 版本号与目录格式不一致
```
（目录名为 1.0.0，却传 --version="V1.0.0"）
```
- 问题：E 编号正则匹配不到目录下已有文件，从 E1 重新计数，造成编号冲突。
- 正确做法：`--version` 与版本目录名格式完全一致。

**错误 4**: 调用方绕过脚本直接 Write 版本目录
```
Write 工具直接写入 C:/项目/账号系统/1.0.0/prd/…
```
- 问题：绕过 save-doc.js 直接写入版本目录，E 编号未登记、`_index.md` 未重建、预保存质量检查未执行，索引与磁盘不一致。
- 正确做法：所有版本目录写入必须经 `save-doc.js`（见"禁止行为"第 3 条）。

### 内容摘要填写规则

- **新文档**（简报、首次 PRD 等）：描述文档主题/范围，如「直播带货全流程」

- **原型快照**（`prototype/E{n}`、`prototype/main`）：描述该快照的页面范围与核心交互，`main` 标注「正式版」，如「正式版原型：登录页+验证码页+协议页」；优先读取快照内 `CHANGELOG.md` 提取

### testcase 质量后缀索引规则

`testcase/` 目录下支持 `测试用例`、`测试用例_中`、`测试用例_高` 三种文档类型。质量后缀以括号形式附加在 E# 列显示，避免同 E 编号重复行：

```
### testcase/
| E# | 最后更新 | 内容摘要（含变更说明） | 负责人 |
|----|----------|------------------------|--------|
| E1（高） | 2026-07-31 | 一键登录测试用例（高质量完整格式）：17条PM验收… | 张三 |
| E1（中） | 2026-07-31 | 一键登录测试用例（中质量简练格式） | 张三 |
| E1 | 2026-07-31 | 一键登录测试用例（标准格式） | 张三 |
```

- **Key 格式**：`版本|testcase|中|E1`、`版本|testcase|高|E1`、`版本|testcase||E1`（无后缀）
- **排序规则**：同 E 编号内按 `标准` → `中` → `高` 顺序排列（子分组升序）
- **向后兼容**：旧索引中 key 为 `版本|testcase||E1` 的条目（无质量后缀），重建时会自动迁移摘要到新 key（中/高两行暂时同摘要，下次 save-doc 时由 AI 补差异化摘要）
- **非标准拆分文件**：模块名插入式命名（如 `测试用例_{模块名}_高_E1.md`）由脚本按独立子分组宽容索引（E# 列显示 `E1（{模块名}_高）`），不并入 中/高 序列；其新鲜度由第五阶段步骤 6 的拆分文件兜底组检测覆盖，不因索引存在而免检

### 最后更新日期

- **普通文档**（brief/prd/report/testcase 等）：取自对应 `.md` 文件的 `LastWriteTime`
- **开发交接产物**（development/ 下目录）：取自对应目录的 `LastWriteTime`
- **原型快照**（prototype/E{n}/、prototype/main/）：取自对应快照目录的 `LastWriteTime`（main 目录随每次 --main 同步更新，反映"最后同步时间"）

索引重建时从磁盘文件系统直接读取时间戳，确保日期始终反映文件实际最后修改时间，而非重建当天。

### 注意事项

- 每次保存文档时，脚本会自动扫描所有版本目录下的文档文件，**重新构建** `_index.md`，确保索引始终与磁盘文件一致。
- 已有摘要的条目会保留原摘要，新增的历史文档会标记为需要 AI 补充摘要（见 `files_needing_ai_summary` 输出）。
- 索引文件位于功能顶级目录（与 `.feature-name` 同级），一个文件覆盖所有版本。

### 触发与分工

- **正常保存**：任何 doc-type 保存后刷新（开发交接目录形态保存时，"开发准备文件夹"行恰好包含刚保存的 E）
- **IndexOnly**：无 `--version` 时扫描 baseDir 下全部版本目录逐个刷新（原型存档 save-version 经 `--index-only` 调用，原型行随之更新）
- **手动重生成**：`node "{本技能源码目录}/scripts/save-doc.js" --base-dir=<功能顶级目录> --version=<版本> --readme-only`（只刷 _README/，不保存文档）
- **存量项目自愈**：版本目录顶层的旧 `README.md` 自动"吸收"收编进 `_README/`（写盘前执行）
- **与 _index.md 分工**：`_index.md` 是全量索引（功能顶级目录、所有版本、含摘要/日期/负责人）；_README/ 是单版本必读指引（评审/开发阅读入口），**不重复索引内容**
- 刷新/门户生成失败不阻塞保存/索引（try/catch）；状态见 JSON 输出 `readme_html` 字段（ok / partial / error / skipped）；`README.md` 不匹配规范文件名，不进 E 编号扫描、不进 `_index.md`、不被保存流程覆盖
- **「整体进度」行分工**：save-doc 只机械判定 `_进度清单.md` 存在性；清单文件本身由路由大脑按 CLAUDE.md「流程清单（进度与待办）」节生成与刷新（PM 说「进度/清单/待办/下一步」触发，技能出口补记点同步），save-doc **不生成、不覆盖、不清理**该文件

### 负向触发（6条）

1. 必选参数缺失但调用方静默执行（不引导、不报错、用默认值替代） — 预期：违反禁止行为 1，必须触发交互式引导或明确报错
2. 临时文件路径不存在或内容为空 — 预期：脚本报错"临时文件不存在" / "临时文件为空"，不落盘
3. 临时文件含未替换占位符（如 `{待确认}`）或未闭合 Mermaid 块 — 预期：预保存质量检查拒绝保存，返回精确行号（`第 {N} 行: …`），修复前不直接重试保存
4. 版本号使用小写 `v` 前缀（如 `v1.0.0`），或与版本目录名格式不一致 — 预期：脚本拒绝（"版本号格式错误"）；格式不一致若被接受，E 编号从 E1 重新计数需人工核对
5. 调用方绕过脚本直接 Write 到版本目录 — 预期：违反禁止行为 3，AI 不得如此操作（E 编号未登记、`_index.md` 未重建）
6. `node` 命令不可用（未装 Node.js / PATH 缺失）时调用 save-doc — 预期：停止流程并提示"请安装或检查 Node.js（LTS）环境后重试"，不静默跳过、不改用 Write 直写（符合 `dependencies` 降级契约与禁止行为 3）

### 边界查询（3条）

1. 版本目录已存在但为空，保存首个文档 — 预期：正确初始化标准目录树并保存；_README/ 刷新为「整体进度」行 + 三表结构并生成 README.html 门户，未产出行标注「未产出」
2. 同一版本同一文档类型已有 E1-E5，保存新文档 — 预期：E 编号递增到 E6，不覆盖历史文件
3. `--summary`/`--author` 含 shell 元字符（`"` `` ` `` `$` `;` `&` 等） — 预期：剔除非法字符后提交并在结果展示中注明，不中断流程
